## Why

`Runtime.run_claude` сейчас завершается заглушкой и не позволяет серверной части получить ответ Claude CLI. Нужен минимальный синхронный способ выполнить один prompt в заданной рабочей директории, чтобы Claude получил контекст нужного worktree, и вернуть результат вызывающему коду.

## What Changes

- Реализовать запуск доступного в унаследованном `PATH` `claude` CLI в режиме печати ответа с обычными локальными настройками и полномочиями, без обхода встроенных ограничений.
- Принимать путь рабочей директории и запускать Claude CLI с этим process cwd.
- Передавать prompt отдельным аргументом процесса без интерпретации shell.
- Возвращать стандартный вывод без изменений при успешном завершении и выбрасывать общее исключение при неуспешном завершении процесса.

## Capabilities

### New Capabilities

- `claude-cli-execution`: Синхронное выполнение prompt через локальный Claude CLI в заданной рабочей директории и получение текстового результата.

### Modified Capabilities

Нет.

## Impact

- Изменяются `lib/runtime.ml`, адаптер вызова в `lib/home.ml` и runtime-проверка в `test/`.
- Используется уже подключённая стандартная библиотека `Unix`; новые зависимости и публичные HTTP-маршруты не добавляются.
- Во время выполнения требуется доступный в `PATH` и настроенный `claude` CLI; реализация рассчитана на текущую macOS/POSIX-среду с `/bin/sh`.
