## Why

Claude-режим сейчас предлагает выбрать Git worktree и запускает новый разговор, поэтому с телефона нельзя продолжить работу с агентом, уже запущенным на компьютере. Нужен список активных агентов всех проектов и собственный чат с явно подключёнными сессиями через публичные интерфейсы Claude.

## What Changes

- **BREAKING**: заменить список worktrees на результат `claude agents --json` без `--cwd` и `--all`: имя, директория, состояние и доступность интеграции. Неподключённые агенты видны, но чат для них недоступен.
- **BREAKING**: удалить создание worktree и сценарий выбранного worktree из интерфейса Claude. Существующие директории и разговоры не удаляются. Приложение не запускает, не останавливает и не возобновляет Claude вместо пользователя.
- Добавить собственный чат для сессий, которые пользователь на компьютере запускает с настроенной интеграцией Channels + Hooks. Терминальный экран, внутренние сокеты Claude и подмена подключения запуском `--resume` исключены.
- Показывать существующую историю пользовательских и текстовых ответов Claude, включая сообщения из терминала, и обновлять текст во время работы. Подробные аргументы и результаты инструментов не входят в обычную ленту.
- Отправлять сообщения работающему агенту; сообщения занятому агенту ожидают обработки. Добавить ответы на запросы разрешений и вопросы пользователя. Кнопка прерывания не требуется; первоначальное доверие проекту и MCP подтверждается на компьютере.
- При потере соединения сохранять отображаемый диалог и введённый текст, блокировать отправку и показывать известную причину. Не повторять сообщения автоматически и не выдавать передачу в канал за подтверждение обработки.
- Сначала проверить осуществимость интеграции на изолированных сессиях. Если публичные интерфейсы не обеспечивают согласованное поведение, остановиться и пересогласовать блокирующее требование, не выпускать урезанную замену молча.

## Capabilities

### New Capabilities

- `claude-agent-chat`: обнаружение активных агентов, подключение сессий, история и живой чат, доставка, разрешения, вопросы и потеря соединения.

### Modified Capabilities

- `startup-agent-mode`: Claude загружает агентов всех проектов, ошибки discovery отображаются в UI; прежний positional root не ограничивает список.
- `eio-http-server`: начальное состояние и события Claude выбирают агента, а не worktree.
- `android-backend-driven-ui`: фоновое обновление выбранного чата без блокировки ввода на время работы агента.
- `ui-command-streaming`: конечные команды обновляют список агентов вместо списка worktrees.
- `claude-output-streaming`: живой UI отражает внешний работающий агент, а не жизненный цикл дочернего `--print`.
- `worktree-navigation`: заменить требования навигации worktree навигацией агента в `claude-agent-chat`.
- `worktree-creation-ui`: удалить требования создания worktree из приложения.
- `worktree-chat-layout`: перенести требование видимого поля ввода на чат агента.
- `worktree-prompt-shortcuts`: удалить требования к кнопкам и полю снятого с использования worktree-экрана; исполнение slash-команд через Channels не обещается.
- `claude-cli-execution`: удалить требования запуска prompt-процесса приложением; чтение списка CLI описано новым контрактом.
- `agent-session-continuation`: удалить требования создания и resume разговора на время открытого экрана; выбор существующего агента описан новым контрактом.

## Impact

- Backend: `lib/runtime.ml`, `lib/home.ml`, `lib/home_components.ml`, `lib/server.ml`; существующие TEA-компоненты списка и диалога служат образцом. Новый bridge нужен для публичного stdio MCP channel и hooks; язык/минимальные зависимости уточняются проверкой протокола, полноценный Agent SDK runtime заранее не добавляется.
- Android: `android/app/src/main/java/io/y2k/remote_client/MainActivity.kt`; существующая сериализация конечных UI-событий сохраняется, получение новых данных не должно удерживать запрос до окончания ответа Claude.
- Проверки и документация: `test/test_runtime.ml`, `test/test_remote_dev.ml`, Android-проверки транспорта и `README.md` с процедурой подключения и ограничениями исследовательского протокола.
- Локальная настройка Claude выполняется отдельно пользователем. Доступность Channels зависит от версии, провайдера и политики организации; development-флаг не отменяет политику. Авторизация отправителя и связывание запросов с конкретной сессией обязательны для удалённых разрешений.
- OpenCode и панель эмулятора сохраняют свои сценарии. Подтверждённая спецификацией цель ещё не означает экспериментально подтверждённую осуществимость.
