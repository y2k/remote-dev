# Handoff: claude-agent-chat

Дата: 2026-09-09. **Работа приостановлена по просьбе пользователя. Следующий шаг — выбор другого подхода, не продолжение реализации текущего плана.**

## Где остановились

Исходная цель: в режиме `claude` показывать активных агентов всех проектов, как `claude agents --json`, вместо worktrees; выбранного агента открывать в собственном мобильном чате.

Созданы `proposal.md`, `design.md`, 12 delta-specs и `tasks.md`. Схема `spec-driven`, локальный OpenSpec root — этот репозиторий. **0/22 задач выполнено.** Артефакты проходят строгую валидацию, но это не подтверждение осуществимости дизайна. Код приложения не изменён. Каталог change на момент передачи — untracked; коммитов не было.

## Что согласовали до обнаружения блокера

- Все проекты, только активные агенты; без архива завершённых.
- Собственный чат, не терминальный экран; только публичные интерфейсы.
- История пользовательских и текстовых ответов Claude, включая терминал; живой текст, без подробного журнала инструментов.
- Отправка занятому агенту без прерывания; кнопка interrupt не обязательна.
- Разрешения и вопросы с телефона; первоначальное доверие проекту и MCP — локально.
- Допустима предварительная настройка интеграции и запуск сессий на компьютере. Неподключённые агенты видны без доступа к чату.
- При обрыве сохранять показанный чат и draft, блокировать отправку, не делать автоматический retry или resume.
- Убрать создание worktree из UI, не удалять существующие директории.

Эти решения привели к плану Channels + Hooks. **Ни одна из альтернатив ниже пользователем ещё не выбрана.** Нельзя молча считать отказ от Channels согласием на SDK, terminal или resume-handoff.

## Доказанный блокер

На Claude Code **2.1.266**, аккаунт в интерфейсе обозначен как **Claude Team**, тестовый интерактивный запуск сообщил:

```text
--dangerously-load-development-channels blocked by org policy (server:probe)
Inbound messages will be silently dropped
Channels are not enabled for your org · have an administrator set channelsEnabled: true in managed settings
```

После отчёта пользователь прямо сказал: **«админы точно не разрешат»**. Поэтому включение Channels не является реалистичным следующим шагом. Не повторять этот эксперимент без новой причины и не обходить политику.

Обычный stdio MCP handshake и два коротких `--print` ответа `READY` прошли. Это не доказывает регистрацию Channels, полноценную работу Agent SDK или возможность подключиться к произвольному живому процессу. Проверки истории, вопросов, разрешений, native OCaml bridge и полного чата не выполнены.

Подробные факты и команды описаны в `design.md`, раздел «Результат первого эксперимента». Временный стенд:

`/var/folders/yn/rfk_wf_941g9wdgstvd2g1_80000gn/T/opencode/claude-agent-chat-spike/`

В нём `probe.py`, конфигурация, `result.txt`, `events.jsonl`, debug log и `command.json`. Временные файлы могут исчезнуть; вывод policy-блокера сохранён в репозитории. Тестовые процессы завершены, что проверено через `pgrep`. Claude мог сохранить тестовую историю и доверие временной директории штатным образом. Политика организации не менялась.

## Обсуждённые альтернативы

| Вариант | Что сохраняет | Что меняет / требует проверки |
| --- | --- | --- |
| Agent SDK управляет запуском | Собственный чат, структурированные события и управление | Не подключается к произвольному внешнему процессу. Нужно согласие на запуск агентов приложением и проверка SDK/auth в окружении |
| Явная передача разговора через resume | Начать в терминале, продолжить в собственном чате с историей | Старый процесс завершается, новый запускается через SDK. Это не live attach; состояние в памяти и выполняющаяся работа не гарантируются |
| `claude attach` в терминальном компоненте | Штатное управление существующим фоновым агентом | Отказ от собственного чата. Не универсальный attach к обычным интерактивным сессиям |
| Только список и просмотр | Наблюдение за уже работающими агентами | Без полноценной отправки/разрешений; ранее пользователь отвергал это сокращение |

Remote Control ранее также сообщил о policy-запрете; публичный API для собственного клиента не установлен. Межсессионные сообщения не эквивалентны HUMAN control и не заменяют permission consent. Внутренние сокеты противоречат согласованному ограничению.

Изученные Happy/HAPI используют wrapper и переход к remote/SDK с resume, а не подтверждённый публичный attach к любому живому Claude. Не принимать рекламное «без потери сессии» за сохранение процесса.

## С чего продолжить разговор

Последний неотвеченный вопрос:

> Что важнее: собственный интерфейс чата или управление тем же агентом, который сейчас работает в терминале? Приемлем ли явный переход между терминалом и приложением через завершение старого процесса и resume истории?

Пользователь попросил отложить этот выбор и сделать handoff. Здесь **handoff означает передачу контекста разработки**, а не выбор варианта передачи Claude-разговора через resume.

После выбора пересогласовать затронутые требования и обновить proposal/design/specs/tasks. До этого не выполнять разделы 2–5, не отмечать feasibility gate пройденным и не архивировать change как завершённый.

## Карта кода

- `lib/home.ml`: сейчас Claude начинает с Worktrees; выбор открывает Worktree.
- `lib/home_components.ml`: worktree-компонент хранит текущий ответ и session ID; OpenCode Sessions/Session — существующий пример списка и чата.
- `lib/runtime.ml`: `claude_process`/`stream_claude` запускают `--print`, затем `--resume`; это не live attach.
- `lib/server.ml`: полный UI в JSON/NDJSON; Claude response связан с продолжительностью дочернего процесса.
- `android/app/src/main/java/io/y2k/remote_client/MainActivity.kt`: `eventInProgress` удерживается до закрытия ответа; бесконечный watch на этом пути заблокирует действия.
- `test/test_runtime.ml`, `test/test_remote_dev.ml`: проверки старых worktree/startup/resume и OpenCode-сценариев.

Backend UI — OCaml TEA. Следовать локальному `AGENTS.md`, сохранять ponytail full: минимальный работающий вариант после понимания нового требования. OpenCode и панель эмулятора вне цели изменения.
