## Context

См. мотивацию в `proposal.md`. `Home` хранит один `screen`; переход по `Route.Worktree` заменяет его новым `Worktree.model`, а `Route.Worktrees` при `back` заново создаёт `Worktrees.model` и запускает загрузку. Набор экранов сейчас закрыт и состоит из worktree-списка и выбранного worktree. Сервер предназначен для одного локального пользователя, поэтому глобальное состояние не меняется в рамках этой работы.

## Goals / Non-Goals

**Goals:**

- Хранить сохранённую модель списка под открытым экраном worktree.
- Восстанавливать её по `back` без выполнения команды загрузки.
- Сделать управление переходом явным как операции со стеком, сохранив типобезопасные варианты экранов, сообщений и событий.

**Non-Goals:**

- Извлечение навигации в отдельную библиотеку.
- Открытая регистрация страниц, first-class modules, GADT или функторный API.
- Изменение HTTP-протокола, рендеринга кнопки возврата или модели многопользовательских сессий.

## Decisions

### Хранить непустой стек явных `screen`

Состояние `Home` будет представлять стек, где верхний элемент является текущим экраном. `view`, `decode` и маршрутизация сообщений продолжают работать только с верхним экраном. Варианты `Worktrees` и `Worktree` остаются контейнерами разнородных моделей.

Это минимально расширяет текущую типовую модель. Альтернатива с универсальными модулями страниц потребовала бы existential/GADT-упаковки несовместимых `model`, `msg`, `action` и `Cmd`, хотя в приложении пока два фиксированных экрана.

### Выражать только необходимые операции навигации

Выбор worktree создаёт новый экран и помещает его поверх текущего. `back` из worktree снимает верхний экран и возвращает сохранённый список без вызова `Worktrees.enter`. Событие `back` на корневом списке сохраняет существующее поведение без ошибки и без изменения экрана.

Отдельные операции `replace` и `reset` не вводятся: для них нет текущего сценария. Это оставляет естественный шов для будущего извлечения: библиотека сможет владеть стековыми операциями, а приложение сохранит закрытый адаптер экранов. Функтор `Navigation.Make(Pages)` рассматривается только при появлении второго потребителя.

### Сохранить выполнение команд текущего экрана

Команды продолжают подниматься из сообщения страницы в `Home`. Переход к worktree выполняет только команду, возвращённую при входе в новый верхний экран; возврат не создаёт новую команду списка.

## Risks / Trade-offs

- [Сохранённый список может устареть, пока открыт worktree] → Это намеренное требование; обновление происходит только по существующему событию загрузки или новому явному требованию.
- [Стек с двумя экранами выглядит как избыточная структура] → Он непосредственно выражает требуемое восстановление модели и не вводит обобщённый фреймворк.
- [Будущей библиотеке может потребоваться иной API] → Не фиксировать API до второго потребителя; сохранить только разделение прикладных экранов и стековой семантики.

## Migration Plan

Изменение не требует миграции данных или развёртывания. После обновления запустить существующий тестовый набор с добавленными проверками сохранённого списка; откат состоит в возврате к предыдущей реализации одиночного экрана.
