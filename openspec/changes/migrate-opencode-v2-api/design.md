# Design

## Context

Мотивация — в `proposal.md`. `lib/runtime.ml` содержит фиксированный TCP endpoint, `Http_request` effect, V1 JSON-декодеры и операции; `lib/server.ml` обрабатывает обычные промпты с быстрым ответом и slash-команды в фоновой fiber. `Sessions` и `Session` потребляют нормализованные runtime-записи. Тесты используют `Runtime.with_http`; большая часть проверок не требует сервиса или Android.

Исследованы live `/api/info` и `/openapi.json` сервера 2.0.24 и исходники соответствующего тега. Подтверждены Basic auth из регистрации, запрос списка папки и `SessionNotFoundError`. Изменяющие запросы при исследовании не выполнялись. Динамический порт наблюдался как 49374, но это не настройка проекта.

Основные источники тега `v2.0.24` в https://github.com/anomalyco/opencode:
- `packages/client/src/service-probe.ts`, `packages/client/src/promise/service.ts`: registration и discovery без запуска.
- `packages/server/src/handlers/session.ts`, `message.ts`: маршруты, ответы, курсоры.
- `packages/core/src/session/store.ts`: точный directory-фильтр до сортировки и LIMIT.
- `packages/core/src/session/message-updater.ts`, `execution.ts`, `session.ts`: retry, асинхронное прерывание, создание без промпта.
- `packages/core/src/form.ts`: список только pending forms.

## Goals / Non-Goals

**Goals:**
- Локализовать перевод V2 в существующем runtime, сохранив TEA и HTTP effect для тестов.
- Дать зависимому UI-change устойчивые операции папки и создания без привязки к wire format.
- Сохранить текущий глобальный список до внедрения папочной навигации.

**Non-Goals:**
- Адаптер нескольких версий, TypeScript sidecar, новый SDK или управление сервисом.
- SSE, автообновление, ответы на permissions/forms, изменения Android renderer.
- Реализация или редактирование артефактов `folder-sessions-in-tabs` в рамках миграции.

## Decisions

### 1. Discovery внутри существующего OCaml-транспорта

Читать `$XDG_STATE_HOME/opencode/service.json` или стандартный путь под home; декодировать URL, PID, optional version/password. Проверять аутентифицированный `/api/info`: успешный ответ V2, совпадение PID и зарегистрированной версии при её наличии. Отсутствующая или испорченная регистрация, несовпадение, 401, недоступность и timeout становятся обычными ошибками операции.

Получать connection context лениво перед высокоуровневой операцией сессии и использовать один снимок endpoint/credentials для её запросов. Следующая операция читает регистрацию заново, поэтому перезапуск OpenCode не требует перезапуска backend. Directory-only команды не инициируют discovery. Ограничить ожидание health check конечным timeout (начальное значение 5 секунд); не переносить этот timeout на потенциально долгий callback команды.

HTTP-транспорт получает адрес и Host из endpoint вместо константы. Использовать локальный HTTP loopback endpoint общего сервиса; неподдерживаемые scheme/нелокальный адрес отклонять до отправки credentials. Поддержать адреса loopback, выдаваемые сервисом, включая IPv4/IPv6 и localhost. Для authentication использовать `Basic base64(opencode:<password>)`; отсутствие поля означает отсутствие заголовка, пустая строка остаётся паролем. Переменные старой authentication policy не участвуют.

Подстановка discovery/регистрации и HTTP в тестах должна работать без чтения реальных credentials. Достаточно явных аргументов небольших функций и существующего effect handler, без нового общего transport framework.

Альтернативы: `opencode api` может запустить сервис и создаёт subprocess на каждый запрос; `Service.ensure()` также управляет процессом. TypeScript `Service.discover()` потребовал бы дополнительный runtime. Регистрационный контракт достаточно мал для прямого OCaml-чтения.

### 2. Один V2-контракт, прежние нормализованные данные

| Операция | Запрос | Успех |
|---|---|---|
| Глобальный список | `GET /api/session?limit=20&order=desc` | `200 {data,cursor}` |
| Папочный список | тот же запрос с percent-encoded `directory` | `200 {data,cursor}` |
| Создание | `POST /api/session`, `{location:{directory}}` | `200 {data:Session.Info}` |
| Метаданные | `GET /api/session/{id}` | `200 {data:Session.Info}` |
| Переписка | `GET /api/session/{id}/message?order=asc` и курсоры | `200 {data,cursor}` |
| Активность | `GET /api/session/active` | `200 {data:{id:{type:"running"}}}` |
| Pending input | `GET /api/session/{id}/permission` и `/form` | `200 {data:[...]}` |
| Промпт | `POST /api/session/{id}/prompt`, `{text}` | `200 {data:Session.Inbox.User}` |
| Команда | `POST /api/session/{id}/command`, `{name,text}` | `204`, пустое тело |
| Stop | `POST /api/session/{id}/interrupt` без resume | `200 {interrupted:boolean}` |

В `Session.Info` директория берётся из `location.directory`, model остаётся `{providerID,id,variant?}`. Отсутствующие agent/model допустимы; отсутствующий title нормализуется в `Без названия` только для отображения. Сервер не переименовывается. V1 workspace context больше не отправляется; существующее optional поле runtime можно оставить `None`, если это сокращает затрагивание UI.

Для операций по ID сервер разрешает актуальную location сам. Не передавать старые `directory/workspace` query/header или agent/model из снимка UI. При refresh читать метаданные заново. Отдельный V1 fallback скрывал бы несовместимость и здесь не нужен.

### 3. Список и создание как основа зависимого UI-change

Сохранить `load_opencode_sessions ()` для текущего глобального экрана; добавить отдельный папочный loader с абсолютным directory и операцию создания. Точные имена дополнительных функций выбрать в существующем стиле runtime при реализации.

Сервер выполняет `WHERE directory = ...`, затем `ORDER BY time_updated DESC, id DESC`, затем `LIMIT 20`: локальная пагинация глобального списка не нужна. Не добавлять `parentID=null`, чтобы без запроса пользователя не исключать дочерние сессии. Для списков достаточно одной страницы независимо от курсора.

Создание возвращает identity/location, но не обязано возвращать title/agent/model. Оно не вызывает prompt. Повтор после неизвестного результата не автоматизируется. Кнопка, переход в чат, защита от повторного UI-нажатия и Back принадлежат `folder-sessions-in-tabs`.

### 4. Полная переписка с пагинацией

Первый запрос `order=asc`, последующие — с opaque `cursor.next`, без `order`. Сохранять порядок страниц и элементов. Конец — отсутствие следующего курсора либо пустая страница: V2 выдаёт курсор даже для последней непустой страницы. Ошибка любой страницы является ошибкой всей загрузки; не выдавать обрезанный transcript за успешный полный результат.

Пользовательское сообщение: `type=user`, `text`; ассистент: `type=assistant`, только `content` с `type=text`. Остальные типы пропускаются, включая служебные записи смены модели, idle и compaction. Список всех сообщений без фильтра сохраняет взаимный порядок ролей; отдельные запросы user/assistant потребовали бы ненужного слияния.

### 5. Статусы и pending input

Один `/active` даёт глобальный снимок активности. Для активных отображаемых строк списка запросить последнее assistant-сообщение (`type=assistant&order=desc&limit=1`). При наличии `retry` нормализовать `Retry` с текстом ошибки; иначе `Busy`. Отсутствие ID в active даёт `Idle`. В деталях использовать уже прочитанную переписку для последнего assistant. Не определять retry только по отсутствию `time.completed`: после неудачной попытки это поле может присутствовать.

`needs_input` — непустой список session permissions или forms. Эти запросы не требуют чтения или отображения содержимого чужих сессий. Получение active map глобально, но дополнительные message-запросы ограничены отображаемыми активными сессиями.

Альтернатива свести всё к Busy проще, но потеряла бы существующее отображение Retry. SSE для устранения дополнительных чтений не соответствует ручному refresh.

### 6. Асинхронная семантика и ошибки

Промпт ожидает только принятия durable inbox item с HTTP 200, не завершения генерации. Декодер проверяет требуемые поля подтверждения. Фоновая fiber slash-команд в `server.ml` сохраняется: callback может выполняться долго, хотя успешный ответ теперь 204 без тела.

Stop принимает оба boolean значения, затем выполняет обычную загрузку состояния. Завершение cleanup может отставать; не подменять Busy на Idle и не вводить ожидание или polling.

`expect_status` больше не превращает любой 404 в `OpenCode_not_found`. Только `_tag=SessionNotFoundError` обозначает исчезновение сессии; `CommandNotFoundError`, `LocationNotFoundError`, прочие HTTP и protocol failures идут в обычную ошибку. Сохранить запрет fallback команды в prompt. Не повторять изменяющие запросы автоматически. Для 401 не включать body; credentials и заголовки не сериализовать в исключения/логи.

## Risks / Trade-offs

- V2 API экспериментальный → fixtures опираются на live schema и исходники 2.0.24; более новые V2 не считаются автоматически проверенными только по major version.
- Несколько чтений не образуют атомарный снимок → отображать полученный серверный снимок и сохранять ручной refresh, не добавляя синхронизацию.
- Полная переписка требует нескольких запросов → сохранить существующее требование полной истории; ограничение истории было бы отдельным продуктовым изменением.
- Дополнительный запрос retry на активную строку → максимум 20 отображаемых строк; не загружать чужие transcripts ради глобального статуса.
- Регистрация меняется между проверкой и запросом → обычная ошибка и повторное discovery при следующем пользовательском действии, без повторной отправки записи.
- UI-change содержит старые предположения → перед его apply согласовать замену Basic-env policy на registration policy, nullable defaults и использование готовых runtime-операций. Не дублировать migration tasks в UI-change.

## Migration Plan

1. Реализовать runtime и регрессионные проверки в текущей ветке, затем минимально адаптировать server/UI-потребителей.
2. Обновить README: OpenCode V2, запуск общего сервиса пользователем, discovery, credentials, ручной refresh и ответы на pending input в OpenCode. Удалить устаревшие инструкции фиксированного 4096 и наследования пароля.
3. Выполнить `dune fmt`, `dune build`, `dune test`; host-side проверки не зависят от Android.
4. Проверить read-only операции на работающем сервисе. Live создание, prompt, command и Stop проверять только после согласования отдельной тестовой сессии, директории, конкретных действий и судьбы созданной сессии. До этого отметить эти проверки как не выполненные.
5. Передать UI-change подтверждённые контракты, runtime signatures, результаты проверок и список файлов/commit. Согласование его артефактов выполнять отдельно.
6. При откате вернуть backend-код; созданные OpenCode-сессии не удалять. Старый backend снова требует своего V1-сервера и не является рабочим fallback для V2.
