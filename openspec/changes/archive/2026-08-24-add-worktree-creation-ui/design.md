## Context

Текущий документ списка worktree уже содержит визуальную кнопку `New`, но без события. Протокол поддерживает кнопки с event и одно поле `input`, значение которого Android-клиент отправляет через envelope при Enter. См. мотивацию в `proposal.md`.

## Goals / Non-Goals

**Goals:**
- Добавить в state machine UI состояние создания worktree.
- Передавать имя новой ветки одним существующим input-событием.
- Вернуть пользователя к списку через существующее событие `back`.

**Non-Goals:**
- Вызов Git, создание ветки или worktree.
- Выбор существующей ветки, start point либо пути worktree.
- Изменения общего протокола компонентов или Android-клиента.

## Decisions

Создание будет отдельным компонентом `New_worktree` с собственными model, action, msg, view, decode и update. `Home` хранит его экранное состояние вместе с моделью списка worktree, маршрутизирует component events и возвращает сохранённый список по `back`. Размещение view и обработки создания в `Worktrees` отклонено, поскольку это смешивает ответственность списка и формы; расширение `Components` или клиентского протокола отклонено, так как оба уже представляют нужные button и input.

Событие отправки имени ветки будет обрабатываться как успешная заглушка: оно не вызывает runtime и оставляет UI создания доступным. Сохранение введённого текста, вывод подтверждения и валидация имени не добавляются, так как будущий Git-эффект определит нужные правила.

## Risks / Trade-offs

- [Пользователь не видит результата отправки] → Это намеренное ограничение заглушки; добавить результат вместе с реальным Git-эффектом.
- [Пустое или некорректное имя достигает обработчика] → В этой стадии нет Git-операции; валидировать через Git при реализации эффекта.
