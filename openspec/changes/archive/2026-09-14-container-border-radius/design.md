## Context

Мотивация и объём описаны в `proposal.md`. В `lib/components.ml` атрибуты контейнеров проходят через конструкторы, варианты `Column`/`Row`, `map` и `to_json`. Уже есть `theme_color` и проверка целых размеров `spacing_size`. Android-модели и строгий парсер находятся в `MainActivity.kt`, где можно повторно использовать `spacingSize` и `themeColor`.

В `UiNodeContent.kt` контейнеры применяют размерные модификаторы, фон, padding и затем рисование gap; положительно взвешенные дети column прокручиваются в существующих обёртках. Дизайн нужен для согласования нового wire-контракта между OCaml и Android и порядка рисования без изменения этой геометрии.

## Goals / Non-Goals

**Goals:** использовать существующие типы цветов, валидацию размеров и штатные Compose-примитивы; сохранить серверную композицию TEA и семантику существующего layout.

**Non-Goals:** отдельные стороны рамки, индивидуальные радиусы углов, пунктир, произвольные RGB-цвета, универсальная система стилей, автоматическое оформление экранов.

## Decisions

### 1. Два независимых атрибута

Wire-форма: `"border":{"width":2,"color":"outlineVariant"}` и `"cornerRadius":12`. Цвет обязателен при выборе border; отсутствие border означает отсутствие линии. Радиус относится к контейнеру, а не к border, чтобы фон и содержимое могли скругляться без рамки. Альтернатива — радиус внутри border — связывает независимые возможности.

В качестве небольших контрактных решений принимаются целые размеры `0..2147483647`, как у spacing; нулевая ширина отключает линию, нулевой радиус не добавляет clipping. Явный ноль сериализуется, отсутствие поля сохраняется. Это исключает неявный цвет и отличается от нативного hairline-поведения нулевой толщины, которое здесь не требуется.

### 2. Расширить текущий API без перестройки модели

В OCaml добавить `Border.t` с width и обязательным `theme_color`, `Border.make ~color width` и параметры `?border`/`?corner_radius` обоим конструкторам. Использовать `spacing_size` для размеров и `color_fields` для роли. Пронести атрибуты через существующие варианты, `map` и `to_json`; не заменять контейнеры универсальным style-объектом ради двух полей.

В Android добавить небольшой тип border и поля в обе модели; runtime-default радиуса — 0. Парсер повторно использует строгие функции размеров и цветов, но отдельно требует наличие border.color, поскольку `themeColor` допускает отсутствие поля для прежних необязательных цветов. Проверять цвет даже при нулевой ширине.

### 3. Одна внешняя форма, нативная отрисовка

Использовать `RectangleShape` для нулевого радиуса и `RoundedCornerShape(radius.dp)` для положительного; штатная форма ограничивает одинаковые радиусы доступными размерами. Один и тот же shape передавать фону, border и clip. Собственная Canvas-отрисовка или дополнительный layout-контейнер не нужны.

Порядок после существующих размерных модификаторов: условный `clip` при положительном радиусе, условный `border` при положительной ширине, фон с общей формой, существующий padding, существующий gap drawing, дети. Border рисуется поверх вложенного содержимого; clip охватывает фон, gap и всех потомков. Ни border, ни radius не добавляют padding. Нулевой радиус не включает новый прямоугольный clip, чтобы старые документы сохранили прежнее поведение переполнения.

Выделить только небольшой общий модификатор оформления, если он устраняет одинаковую цепочку в двух ветках. Существующий `GapDrawing`, weight-обёртки и scroll-механику использовать без переустройства. Альтернатива с дополнительным inset на толщину рамки меняла бы размеры детей и противоречит согласованному поведению.

## Risks / Trade-offs

- Рамка может перекрыть край содержимого при нулевом padding → это согласованная overlay-семантика; отступ выбирает сервер существующим padding.
- Ошибка порядка модификаторов может обрезать только внутреннюю область или спрятать рамку за ребёнком → проверить пиксели углов и видимость рамки поверх сплошного дочернего фона для row и column.
- Rounded clip изменяет видимость выступающих потомков → применять только при положительном радиусе и проверить прокручиваемого ребёнка вместе с padding и цветным gap.
- Нулевая ширина в Compose может означать hairline → не добавлять border-модификатор при нуле.
- Старый клиент игнорирует незнакомые поля → сначала обновить клиент; гарантия нового оформления относится к обновлённому клиенту.

## Migration Plan

Изменений хранимых данных нет. Поставить Android-поддержку и серверный API; новые поля использовать после обновления клиента. Для отката оформления достаточно перестать передавать атрибуты. Старые документы должны проходить прежние проверки без изменений.

Проверки добавить в существующие `test/test_remote_dev.ml` и `BackendUiParserTest.kt`: сериализация и mapping, строгий парсинг, геометрия и пиксели рамки/скругления. Устройства для Android-проверок — только `abf51f11`; недоступность устройства блокирует эти проверки.
