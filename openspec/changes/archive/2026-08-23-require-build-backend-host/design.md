## Context

Сейчас URL backend задан в Kotlin, а IP для cleartext HTTP отдельно задан в XML. Android network security config статичен внутри APK, поэтому одного runtime-значения недостаточно для безопасного изменения IP. См. мотивацию в `proposal.md`.

## Goals / Non-Goals

**Goals:**
- Использовать `backendHost` из локального `local.properties` как источник IP для конкретной сборки.
- Передать из этого свойства origin клиенту и ограничить cleartext HTTP тем же хостом.
- Не допустить создание APK, если IP не задан ни в одном поддерживаемом источнике.

**Non-Goals:**
- Не добавлять runtime-экран, сохранение настройки или поддержку выбора backend в уже собранном APK.
- Не менять схему, порт `8080` или протокол HTTP backend.
- Не включать cleartext HTTP глобально.

## Decisions

### Локальное свойство с CLI override

Android-модуль читает `backendHost` из `local.properties`; значение `-PbackendHost` имеет приоритет для одной сборки. Это сохраняет IP вне version control и позволяет Android Studio собирать проект без настройки параметров Gradle в IDE.

Альтернатива: принимать только Gradle project property. Отклонено, поскольку Android Studio не передаёт её при обычной синхронизации и сборке. `gradle.properties` не используется, чтобы локальный IP не попадал в version control.

### Один источник для URL и network security config

Сборка формирует URL `http://<backendHost>:8080/` для клиентского кода и генерирует XML network security config для того же значения. Статический XML с IP удаляется.

Альтернатива: передавать адрес только в клиентский код. Отклонено: Android заблокирует cleartext HTTP для нового IP. Альтернатива: разрешить cleartext глобально. Отклонено, поскольку это ослабляет существующее ограничение адреса.

### Сборочная, а не runtime-настройка

Адрес встраивается в APK. Смена сети требует новой сборки после изменения `local.properties` либо с другим `-PbackendHost`.

Альтернатива: runtime-настройка. Отклонено как ненужная для текущего development-сценария и более широкая по объёму.

## Risks / Trade-offs

- [Смена сети требует пересборки APK] → Локальная настройка и разовый CLI override делают это предсказуемым.
- [Неверно переданный адрес приводит к недоступности backend] → Значение применяется одинаково к URL и cleartext policy, без риска рассинхронизации двух IP.
- [В `local.properties` отсутствует IP] → Сборка завершится ранней понятной ошибкой; инструкция показывает нужную настройку и CLI override.

## Migration Plan

1. Удалить фиксированный IP из Kotlin и статического network security config.
2. Добавить `backendHost` в `local.properties`, CLI override и генерацию производных Android-конфигураций.
3. Обновить инструкцию debug-сборки на настройку `local.properties`.
4. Для отката вернуть предыдущую статическую конфигурацию; APK, уже собранные с новым свойством, не требуют миграции данных.
