# Design

## Context

Мотивация описана в `proposal.md`. `Project_tabs` уже владеет моделью, событиями и чистой `view` в `lib/home_components.ml`. Сейчас `view` собирает вложенные `row` и кнопки: активная подпись имеет `*`, закрытие — `X`, создание — `+`. Горизонтальная прокрутка и закреплённая кнопка создания уже существуют. Android разбирает узлы в `MainActivity.kt` и отображает их в `UiNodeContent.kt`.

Пользователь подтвердил дизайн в обсуждении: семантический компонент, `Tab N`, текущие темы и Roboto 14 sp, верхняя линия 2 dp, иконки и минимум 48 dp на действие, автоматическая видимость новой активной вкладки, стандартная клавиатура. Экран Stitch Projects имеет приоритет над отличающимся описанием рамки в `.stitch/DESIGN.md`.

## Goals / Non-Goals

**Goals:** сохранить TEA на OCaml и отделить данные полосы от нативной отрисовки; проверять контракт на границе JSON; сохранить самостоятельные действия выбора и закрытия.

**Non-Goals:** переименование вкладок по проекту, перестановка, сохранение между перезапусками, новые команды клавиатуры, изменения карточек, чата, эмулятора или глобальной палитры. Универсальный API иконок и декораций не вводится.

## Decisions

### Approaches

Выбран пользователем отдельный семантический `tab_strip`. Альтернатива — расширить общие контейнеры кликабельностью, частичными границами и иконками; это увеличивает API ради одного компонента. Готовая стандартная Material-полоса требует переработки индикатора и независимого закрытия для соответствия Stitch, поэтому используем стандартные Compose-примитивы внутри собственного небольшого renderer.

### Формат и интерфейсы

Технический выбор реализации: `tab_strip` содержит `tabs` и `addEvent`; каждый элемент — `id`, `label`, `selected`, `selectEvent`, `closeEvent`. `id` — непрозрачная непустая строка, для текущих вкладок `string_of_int id`. События остаются JSON-массивами. Идентификаторы уникальны; непустая полоса имеет ровно одну выбранную вкладку. Parser проверяет поля без преобразования типов.

В `lib/components.ml` добавить `type 'event tab = { id : string; label : string; selected : bool; select_event : 'event; close_event : 'event }`, вариант `Tab_strip of 'event tab list * 'event` и `tab_strip ~add_event tabs`. Существующие `map` и `to_json` обрабатывают все события полосы. `Project_tabs.view` строит этот узел, сохраняя существующую колонку контента и обёртки событий.

Android: `UiTab(id: String, label: String, selected: Boolean, selectEvent: UiEvent, closeEvent: UiEvent)` и `UiNode.TabStrip(tabs: List<UiTab>, addEvent: UiEvent)` в `MainActivity.kt`. Отрисовку вынести в `TabStripContent.kt`: `TabStripContent(node: UiNode.TabStrip, onEvent: (UiEvent) -> Unit, eventInProgress: Boolean, modifier: Modifier = Modifier)`. Вызов идёт из `UiNodeContent` и использует существующий путь отправки событий.

### Оформление

Точные роли и размеры заданы в delta spec. Дополнительные локальные параметры реализации: отступ полосы 12 dp по горизонтали и 2 dp по вертикали; промежуток между вкладками и перед кнопкой добавления 8 dp; горизонтальный отступ подписи 12 dp, вертикальный 4 dp. Используется существующий `labelLarge` (14/21 sp, weight 500, zero letter spacing). Фон выбранной вкладки прямоугольный по экрану Stitch. Кнопка добавления имеет радиус 8 dp. Иконки — локальные VectorDrawable `ic_close.xml` и `ic_add.xml`, без шрифтов и зависимостей. Области выбора и закрытия — соседние элементы, а не вложенные клики; линия 2 dp рисуется над всей выбранной вкладкой без изменения её размеров.

### Прокрутка и доступность

Внешний `Row` содержит растягиваемую горизонтальную полосу и закреплённый add. Вкладки имеют стабильные ключи `id`. Состояние прокрутки хранится локально как состояние представления; выбранная вкладка берётся только из backend. При первой отрисовке и изменении выбранного `id` после измерения вызывается нативное приведение выбранной вкладки в видимость. При обновлении документа с тем же `id` повторного скачка нет. Если вкладка шире viewport, показывается её начало и сохраняется возможность ручной прокрутки к закрытию.

`selectableGroup` и `selectable` с ролью вкладки отделены от кнопки закрытия. Все три вида действий используют стандартные ripple, фокус и Enter/Space. Доступные подписи — `Close Tab N` и `Add tab`, согласованно с существующими английскими описаниями действий. Блокировка запросов применяется ко всем действиям, без оптимистического выбора и очереди.

## Risks / Trade-offs

- Минимум 48 dp делает полосу выше desktop-образца → сохраняем размеры иконок и компактные отступы, проверяем масштаб 1.25 и 2.0.
- Смена документа может сбрасывать локальную прокрутку → сохраняем состояние по месту компонента, эффект привязываем к выбранному `id`, тестируем Refresh после ручной прокрутки.
- Закрытие рядом с выбором может отправить два события → соседние неперекрывающиеся цели и тест точного события.
- Старый клиент отвергает новый узел → совместное обновление backend и APK.
- Уже известный сбой divider-теста (issue #3) → отдельно отражаем в результатах, не принимаем его за регрессию вкладок.

## Migration Plan

Сначала завершить протокол, renderer и проверки; установить обновлённый APK на устройство из `.envrc`, затем перезапустить backend. Проверить пустую и переполненную полосу, две темы, навигацию и доступность, сохранить снимки в `~/Desktop/remote-dev-tabs`. Восстановить исходные тему и масштаб. При откате вернуть совместимую пару backend/APK. Синхронизация specs и архивирование выполняются после завершения изменения.
