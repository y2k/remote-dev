# Design

## Context

Мотивация описана в `proposal.md`. Сейчас `Session.header` в `lib/home_components.ml` выводит четыре строки с отступами 12 dp: подпись, крупный `Heading`, путь и статус. `Session.view` уже выделяет переписке оставшуюся высоту весом 1, оставляя шапку и ввод content-sized. Вкладки принадлежат `Project_tabs`, а подпись агента и правая панель — `Home.view`.

Основная спецификация требует постоянно видимый путь и запрещает действия шапки; delta явно заменяет эти требования. Это небольшое изменение, но способ раскрытия пути и поведение длинных значений требуют фиксации до реализации.

## Goals / Non-Goals

**Goals:**
- Уменьшить высоту стандартной шапки до компактной строки, используя существующие компоненты.
- Сохранить полный доступ к данным сессии и существующее распределение высоты.

**Non-Goals:**
- Изменение вкладок, их размеров, текста, расположения и событий.
- Изменение сообщений, шрифтов тела переписки, поля ввода, подписи агента, правой панели и Claude-экранов.
- Точное воспроизведение вымышленных сообщений, подсветки кода и временных меток из макета.

## Decisions

### Approaches

Пользователь выбрал **A: постоянно видимое название и статус в компактной строке**. Вариант B скрывал название вместе с путём за строкой раскрытия: экономия немного больше, но контекст разговора хуже виден. Ранний вариант с названием внутри вкладки отклонён пользователем; вкладки не затрагиваются.

### Композиция шапки

Уточнение пользователя: название, статус и кнопку центрировать по вертикали. Существующий Android `Row` по умолчанию прижимает детей к верху; добавить ему опциональный boolean `centerVertically` (по умолчанию false) и включить только для строки шапки. В Compose использовать `Alignment.CenterVertically`; это также центрирует обёртки weighted-детей и работает при переносе текста. Не использовать фиксированные отступы, зависящие от размера шрифта.

В существующем `Session` использовать горизонтальный `row` с названием в стиле `Session_title`, статусом `Caption` и компактной кнопкой `Сведения`. Названию выделить остаток ширины, статусу — ограниченную долю строки, кнопке — её естественную ширину. Убрать подпись `OpenCode session`, постоянный путь и крупный стиль `Heading`. Сохранить тематический фон и небольшой горизонтальный отступ; минимальную высоту задаёт существующий touch target кнопки 48 dp.

Существующий `Text` переносит строки и не поддерживает ellipsis. Сохраняем перенос длинного названия и полного retry-сообщения вместо расширения протокола. Поэтому 48 dp — ориентир для обычных значений, а не жёсткое ограничение при большом системном шрифте.

### Сведения по запросу

Решение исполнителя: вместо новой иконки/диалога использовать существующую компактную текстовую кнопку `Сведения`; она раскрывает полный путь строкой `Code` под компактной шапкой и повторным нажатием скрывает его. Это реализует действие из макета без нового базового компонента. Путь переносится обычным рендерером.

Добавить в `Session.model` булево состояние раскрытия с начальным значением false, а в `Session.msg` — локальное событие переключения. Чистый `view` строит обе части шапки; `update` переключает только это состояние и возвращает `Cmd.none`. Ответы загрузки обновляют данные сессии, сохраняя раскрытие. Каждая открытая страница уже хранит свой `Session.model`, поэтому вкладки не требуют изменений.

Не менять количество/порядок верхнеуровневых областей `Session.view`: раскрытые сведения остаются внутри существующей области шапки. Остальные события и server-held prompt сохраняются текущими record updates.

## Risks / Trade-offs

- Длинные заголовки и retry-текст увеличивают высоту → сохраняем доступность полных значений; проверяем на устройстве с масштабом шрифта 125%.
- Макет Stitch сам перерисовывает вкладки → ориентир для их сохранения — исходный скриншот, а для шапки — итоговый скомпонованный вариант A. Сравниваем геометрию вкладок на реальном устройстве до/после.
- Раскрытие пути временно уменьшает переписку → состояние по умолчанию закрыто, повторное нажатие возвращает место.
- Android сбрасывает локальный текст поля при новом документе (`remember(node, LocalUiDocument.current)`) → этот план не обещает нового поведения сохранения локального черновика; server-held prompt сохраняется. Общая переработка черновиков требует отдельного изменения.

## Migration Plan

После уточнения о центрировании обновить Android-клиент и backend, затем проверить строку на устройстве. Старые документы без `centerVertically` сохраняют прежнее выравнивание. Миграций данных нет.
