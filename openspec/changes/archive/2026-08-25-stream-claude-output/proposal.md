## Why

Сейчас сервер ждёт завершения Claude CLI и возвращает клиенту единственный UI-документ. Длительные ответы не видны пользователю до конца выполнения, хотя Claude CLI уже умеет выдавать JSON-дельты текста.

## What Changes

- Запуск Claude CLI будет читать его `stream-json` stdout по мере поступления и извлекать текстовые дельты ответа.
- Ответ на `run_claude` станет HTTP-потоком компактных NDJSON UI-документов; каждый документ будет содержать накопленный текст ответа.
- Android-клиент будет читать поток UI-документов построчно и обновлять экран после каждой корректной строки.
- Явный 15-секундный HTTP request timeout клиента будет убран, чтобы не прерывать длительный, но активный поток.
- Обычные UI-события сохранят текущий ответ одним JSON-документом.

## Capabilities

### New Capabilities
- `claude-output-streaming`: Потоковая передача накопленного текстового ответа Claude в backend-defined UI-документах и инкрементальный рендеринг Android-клиентом.

### Modified Capabilities
- `claude-cli-execution`: Вместо ожидания полного stdout Claude CLI передавать текстовые дельты его JSON-потока вызывающему коду и сохранять сообщение об ошибке при неуспехе процесса.

## Impact

- Затронуты `lib/runtime.ml`, `lib/home.ml` и `lib/server.ml` для потокового запуска, накопления output и chunked HTTP-ответа.
- Затронуты `android/app/src/main/java/io/y2k/remote_client/MainActivity.kt` и Android-тесты для чтения NDJSON и обновления Compose state.
- Меняется HTTP-представление только успешного события `run_claude`: `application/x-ndjson` вместо одного `application/json` документа.
- Новые зависимости не требуются.
