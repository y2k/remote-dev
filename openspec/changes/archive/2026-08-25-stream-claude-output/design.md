## Context

См. `proposal.md`. `Runtime.run_claude` сейчас читает весь stdout до завершения процесса, `Home.dispatch` синхронно исполняет command, а `Server.respond` формирует response с `content-length`. Android ждёт весь response через `bodyAsText()`. Claude CLI поддерживает newline-delimited `stream-json`; текст приходит в `stream_event`, где `event.type` равен `content_block_delta`, а `event.delta.type` равен `text_delta`.

## Goals / Non-Goals

**Goals:**
- Передавать текст Claude из одного `run_claude` в текущий UI по мере его генерации.
- Сохранить backend-defined UI-документ единственным форматом, который понимает Android UI.
- Не менять поведение остальных event responses и не добавлять зависимости.

**Non-Goals:**
- Не показывать вызовы инструментов, reasoning или служебные события Claude.
- Не поддерживать отмену Claude при закрытии Android response, возобновление потока или несколько параллельных разговоров.
- Не заменять односторонний response SSE или WebSocket.

## Decisions

### Преобразовывать CLI-поток на сервере

`Runtime` будет запускать текущий CLI-вызов с `--output-format stream-json --verbose --include-partial-messages` и читать stdout по строкам. Из каждой валидной JSON-записи будут извлекаться только `text_delta`; прочие известные и неизвестные корректные сообщения игнорируются. Это не допускает передачи меняющегося внутреннего протокола Claude в Android и предотвращает дублирование текста из финального `result` сообщения.

Альтернатива, передать сырой `stream-json` в Android, отклонена: Android пришлось бы знать типы событий Claude и самостоятельно собирать ответ вместо backend-defined UI.

### Передавать полные UI-снимки как NDJSON

Для `run_claude` сервер сначала отправляет `application/x-ndjson` без `content-length`, затем после каждой текстовой дельты сериализует текущий `Home` в одну компактную JSON-строку и записывает её в HTTP body. Модель `Worktree.output` накапливает дельты; это позволяет существующему renderer получить полный экран без протокола patch-операций.

Альтернатива, передавать `{ "type": "delta", "text": ... }`, отклонена: она потребует отдельного protocol parser и логики применения patch в Android. Полные снимки увеличивают объём при очень длинном ответе, но для текущего локального однопользовательского инструмента это меньшая сложность.

### Разделить один response и поток на HTTP boundary

После разбора request сервер определяет `run_claude` и использует streaming writer только для него. Остальные события продолжают пользоваться существующим request-response путём и `application/json`. Ошибку процесса после отправки заголовков нельзя выразить HTTP status; она становится последним UI-снимком с `error`.

Альтернатива, сделать NDJSON форматом всех событий, отклонена: это ломает текущий протокол без пользы для событий, которые никогда не имеют промежуточных состояний.

### Читать response в Android инкрементально

Клиент выбирает parser по `Content-Type`: для `application/x-ndjson` читает body channel до строк и присваивает `ScreenState.Content` после каждой разобранной строки; для текущего JSON сохраняет `bodyAsText()` путь. `eventInProgress` остаётся true до закрытия потока, поэтому существующее отключение input и button защищает от повторной отправки. Явный 15-секундный request timeout удаляется, поскольку Claude может законно отвечать дольше.

Альтернатива, читать `bodyAsText()` и разбивать результат после закрытия, отклонена: это сохраняет исходную задержку и не даёт инкрементального UI.

## Risks / Trade-offs

- [Полные снимки повторяют уже переданный output и растут квадратично с числом дельт] → принять для текущего локального применения; перейти на delta protocol только при измеренной проблеме с размером или частотой обновлений.
- [Невалидная строка stdout не является корректным Claude stream event] → завершить запуск ошибкой и отправить финальный UI-документ с error, не отображая частичные данные как завершённый результат.
- [Клиент отключается во время запуска] → процесс не отменяется в рамках change; добавить управление дочерним процессом только при явном требовании отмены.
- [Глобальный `Home.state` уже разделён между HTTP-клиентами] → change не расширяет существующую однопользовательскую модель; параллельные сессии остаются вне scope.

## Migration Plan

1. Развернуть сервер и Android-клиент вместе, поскольку клиент должен уметь читать response нового media type.
2. При rollback вернуть серверу существующий единственный JSON response и использовать предыдущую сборку Android-клиента.
3. Обновить README с тем, что только `run_claude` использует `application/x-ndjson`.
