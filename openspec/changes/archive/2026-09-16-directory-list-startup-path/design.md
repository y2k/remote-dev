## Context

Мотивация описана в `proposal.md`. `Runtime.parse_args` уже разбирает один позиционный путь, но сохраняет его только в `Claude { root }` и запрещает для OpenCode. `Home.init` игнорирует окружение и передаёт `Sys.getcwd ()` в `Directories.init`. Компонент `Directories` уже хранит корень в модели, использует его при обновлении и строит пути кликов через `Filename.concat`.

Текущие спецификации явно требуют игнорировать путь Claude для списка и запрещать путь OpenCode. Delta-спецификации заменяют эти требования согласно ответам пользователя. Изменение проходит через `runtime`, `home` и сопоставления окружения в `server`, поэтому решение фиксируется здесь.

## Goals / Non-Goals

**Goals:**
- Передавать выбранный корень через существующее окружение backend до TEA-модели `Directories`, сохраняя чистый `view` и текущий цикл загрузки.
- Привязать относительный путь к рабочей директории запуска один раз.

**Non-Goals:**
- Менять алгоритм выбора подкаталогов, Android-протокол, навигацию или источники каталогов сессий OpenCode.
- Вводить отдельную систему конфигурации или менять рабочую директорию процесса через `chdir`.

## Decisions

1. **Добавить `root` к существующему варианту `OpenCode`.** Использовать `Claude of { root : string } | OpenCode of { root : string }`. В Claude значение обслуживает существующие операции репозитория и список; в OpenCode — только список. Это сохраняет передачу окружения из `bin/main.ml` через `Server` в `Home` без нового контейнера настроек и дополнительного аргумента каждого уровня. Сопоставления OpenCode в `lib/home.ml`, `lib/server.ml` и тестах адаптируются к полезной нагрузке, не меняя выбор провайдера.

2. **Оставить стандартный разбор `Arg`.** Принимать один необязательный позиционный `[directory]` для обоих режимов. Сначала получить рабочую директорию запуска; при отсутствии аргумента использовать её, а относительный аргумент сделать абсолютным через `Filename.is_relative` и `Filename.concat`. Обновить usage и сообщение о лишнем пути. Отдельный флаг не нужен: пользователь подтвердил позиционный интерфейс.

3. **Не требовать существования пути во время разбора.** Абсолютный путь не обязан быть каноническим: `.` и `..` допустимы, разрешение символических ссылок не требуется. Это зафиксированное техническое допущение сохраняет существующую обработку ошибок чтения в UI. `Unix.realpath` на этапе разбора мог бы завершить запуск для отсутствующего каталога и нарушить этот контракт.

4. **Инициализировать существующий компонент корнем из окружения.** `Home.init` выбирает `root` любого режима и передаёт его в `Directories.init`. Начальная загрузка после результата эмулятора, refresh, отображение корня, пути кликов и ошибки уже используют модель компонента. Изменение в одном месте покрывает эти пути без отдельных обработчиков.

5. **Расширить существующие проверки.** В `test/test_runtime.ml` заменить ожидание отказа OpenCode с путём проверкой принятия и проверить абсолютный, относительный, отсутствующий и лишний аргумент для обоих режимов. В `test/test_remote_dev.ml` проверить передачу корня из разобранных аргументов в начальный экран, чтение и refresh выбранного каталога, абсолютный путь строки и ошибку явного недоступного корня. Использовать существующие тестовые средства и подмены внешних вызовов.

## Risks / Trade-offs

- [Запуск Claude с явным путём изменит содержимое стартового списка] → отметить изменение в `README.md` и показать примеры для обоих режимов и запуска без пути.
- [Новый payload OpenCode затронет сопоставления вне инициализации] → обновить все использования конструктора и проверить сборкой; сохранить серверные каталоги сессий и проверки разделения провайдеров.
- [Относительный путь мог бы нарушить абсолютные пути событий] → разрешать его при разборе аргументов и проверять строку события в регрессионной проверке.

## Migration Plan

Обновить backend и документацию, затем перезапустить процесс с нужным позиционным путём. Миграции данных нет. При откате backend запуск OpenCode с путём снова будет запрещён; убрать этот аргумент, чтобы запустить предыдущую версию.
