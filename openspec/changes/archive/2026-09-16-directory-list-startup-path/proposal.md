## Why

Сейчас стартовый список всегда читается из рабочей директории backend, даже когда при запуске Claude передан другой путь. Пользователю нужно выбирать каталог для списка аргументом запуска в обоих режимах агента.

## What Changes

- Необязательный позиционный путь задаёт корень списка подкаталогов для Claude и OpenCode; без пути используется рабочая директория на момент запуска.
- Относительный путь разрешается относительно рабочей директории запуска и сохраняется как абсолютный путь для загрузки, обновления и событий строк.
- **BREAKING**: в Claude переданный путь теперь определяет также источник стартового списка, вместо прежнего безусловного использования рабочей директории.
- В OpenCode разрешается позиционный путь; он задаёт только источник списка, а каталоги сессий по-прежнему предоставляет сервер OpenCode.
- Сохраняются текущие правила списка: до десяти непосредственных реальных подкаталогов, сортировка по времени изменения, исключение файлов и символических ссылок, обработка ошибок и обновление.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `startup-directory-list`: корень списка выбирается из аргумента запуска с запасным значением текущей рабочей директории.
- `startup-agent-mode`: оба режима принимают один необязательный позиционный путь; в Claude он также остаётся корнем репозитория.

## Impact

Затрагиваются разбор аргументов и тип `Runtime.environment` в `lib/runtime.ml`, инициализация `Home.init` в `lib/home.ml`, сопоставления режима OpenCode и тестовые значения окружения. Будут обновлены проверки в `test/test_runtime.ml`, `test/test_remote_dev.ml` и примеры запуска в `README.md`. Используются существующие `Arg`, `Filename` и компонент `Directories`; новые зависимости не нужны.
