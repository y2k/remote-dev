## Why

В `lib/home.ml` каждый экран определяет отдельный тип `action` наряду с `msg`, хотя оба представляют события одного state machine на разных этапах обработки. Это дублирует типы и обёртки в `Home`, не меняя внешний протокол UI.

## What Changes

- Удалить типы `action` из экранов `Worktrees`, `New_worktree` и `Worktree`.
- Использовать соответствующие варианты `msg` как события, создаваемые view, сериализуемые в JSON и декодируемые из запросов.
- Убрать отдельный контейнер `Home.event`; view и сериализация будут работать с `Home.msg`.
- Сохранить имена JSON-событий, формат request envelope, переходы между экранами, вывод ошибок и streaming без изменений.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Это внутренний рефакторинг без изменения требований или наблюдаемого поведения.

## Impact

- Затронут `lib/home.ml` и существующие unit-тесты этого модуля, если они покрывают типы событий.
- Клиент Android, HTTP API, зависимости и существующие OpenSpec-спецификации не меняются.
