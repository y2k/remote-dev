# Design

## Context

Мотивация и объём — в `proposal.md`. `Home.model` сейчас содержит один `screen` и общий `emulator`; `Home.init` создаёт `Directories` в обоих режимах. `Directories` уже реализует список, загрузку, сохранение предыдущих данных при ошибке и log-only клик. `Server` хранит одну модель в `Atomic`, декодирует события и возвращает полные документы.

Проверенный клиентский путь: `MainActivity.refresh` отправляет `POST` с `Refresh`, а `renderResponse` заменяет полный UI. Начальный `GET` только читает текущую модель. Какие данные перечитать, решает `Home.update`; клиент не знает ни текущего экрана, ни табов. `UiNodeContent` поддерживает существующие кнопки и контейнеры, вертикальную прокрутку положительно взвешенных детей column, но не горизонтальную прокрутку row.

Design нужен из-за изменения модели состояния и связанной инициализации/маршрутизации в нескольких backend-модулях. Существующие specs требуют стартовый список в обоих режимах; delta-specs явно меняют это для OpenCode. План `claude-agent-chat` не является зависимостью.

## Goals / Non-Goals

**Goals:** изолировать управление табами в небольшом TEA-компоненте, сохранить универсальный Android-протокол и единый источник данных списка.

**Non-Goals:** универсальная система рабочих пространств, отдельный стек навигации или чат на таб, дисковое хранение, новый транспорт, новый UI-тип `tabs`, индивидуальная позиция прокрутки таба.

## Decisions

### 1. Самодостаточный компонент табов на backend

Добавить `Project_tabs` в `home_components.ml` с `model`, `msg`, чистым `view` и `update`. Модель содержит упорядоченные идентификаторы табов, `active : id option`, монотонный счётчик и одну `Directories.model`. В `Home.screen` добавить вариант оболочки табов; OpenCode инициализирует его без табов, Claude сохраняет текущую ветку.

События создания, выбора и удаления обрабатывает компонент; вложенные directory-события поднимаются обычным `Cmd.map`. `Home` продолжает владеть единственным emulator и общими `Refresh`/`Back`. Это меньше изменений, чем превращать все существующие экраны и агентские команды в универсальные tab-scoped сообщения.

Инвариант: при пустом списке active отсутствует, при непустом указывает на существующий таб. Удаление активного выбирает следующий таб, иначе предыдущий. Неизвестный ID не меняет модель. Счётчик не сбрасывается при удалении всех табов, только при рестарте процесса.

### 2. Общие данные списка, без per-tab кешей

Все табы показывают один startup root, а индивидуальное содержимое табов пока не запрошено. Поэтому одна `Directories.model` переиспользуется в view выбранного таба. Альтернатива — копировать одинаковые списки в каждый таб — добавляет вопрос синхронизации без полезного поведения.

При переходе от нуля табов к одному выполнить загрузку. Дополнительный таб и переключение используют текущие данные. Удаление последнего таба скрывает список; следующее создание снова перечитывает корень. Последний успешный список может оставаться внутренним кешем для существующего поведения ошибок, но при нуле табов не отображается.

Общий `Refresh` при наличии табов перечитывает этот единственный список и возвращает весь UI; при нуле табов возвращает пустую оболочку без чтения каталогов. Он сохраняет табы и активный ID. Refresh панели эмулятора сохраняет прежний отдельный смысл. Не добавлять tab ID в клиентский Refresh и не объявлять обновление «только активного таба».

Это проектный default для ревью, а не ранее согласованное требование о разных состояниях проектов. Отдельные данные на таб понадобятся только когда появится различающееся содержимое.

### 3. Горизонтальная полоса табов

Сохранить внешний row `2:1` с themed divider и общей панелью эмулятора справа. Слева расположить agent label, однострочную горизонтальную полосу табов и ниже содержимое активного таба. Каждый таб содержит кнопку выбора `Tab N` и кнопку удаления; активный таб отмечен фоном `primaryContainer` и текстовым маркером. Табы идут в порядке создания, без переноса на новые строки. При нуле табов содержимое списка проектов отсутствует.

Полоса — внешний weighted row `[1; 0]`: первая область занимает оставшуюся ширину и содержит горизонтально прокручиваемый row табов, вторая — всегда видимую кнопку `+`. Сама полоса имеет высоту по содержимому; список проектов получает оставшуюся высоту и сохраняет вертикальную прокрутку. Горизонтальная прокрутка ограничена первой областью, не двигает проекты и эмулятор. При нуле табов пустая первая область сохраняет `+` справа.

Для этого добавить необязательный boolean `horizontalScroll` к row, по умолчанию `false`. Backend constructor, `Components.map` и сериализация сохраняют поле; отсутствие настройки не меняет существующий JSON. Android parser и модель `UiNode.Row` принимают поле, рендерер использует нативный Compose `horizontalScroll(rememberScrollState())` в ограниченной родителем ширине. Небулевое значение, включая null, отклоняется. Прокручиваемый внутренний row не имеет `weights`; комбинация `horizontalScroll: true` и `weights` отклоняется, поскольку распределение весов по неограниченной ширине не нужно для этого layout. Внешний row с весами сам не прокручивается. Область scroll должна корректно ограничивать drawing, сохранять padding/gap и не перекрывать `+`.

Это общее свойство layout, не новый тип `tabs`: Android не знает идентичностей табов и не принимает решений о выборе, удалении или Refresh. По уточнению пользователя кнопка удаления имеет подпись `X`; `x` в схеме обозначает эту кнопку. Вертикальный список отвергнут пользователем; новая горизонтальная компоновка и закреплённый `+` согласованы. Новых зависимостей не требуется.

### 4. Инициализация, HTTP и внутренние результаты

В `Home.init` сохранить общий запуск загрузки эмуляторов, но завершение `Initialize_emulator` в OpenCode не должно запускать директории или создавать таб. Первый таб инициирует конечный directory-command через существующий JSON/NDJSON механизм.

Добавить обработку нового варианта screen в исчерпывающие matches `server.ml`, включая проверки запуска старых prompt/command путей: оболочка табов не запускает их. В `Server.decode` отклонять клиентские сообщения внутренних результатов directory-load и в новой вложенной форме, как уже отклоняется `Directories.Loaded`. Проверки этой границы обязательны: opaque events не дают клиенту права подменять содержимое списка.

GET и Refresh не вызывают reset/initialize. `Back` в оболочке табов — no-op. Клик по проекту проходит через существующий log-only update и не открывает проект или сессию.

### 5. Подтверждённое и defaults

Подтверждено: ноль табов при запуске; создание, выбор, удаление всех табов; список проектов в каждом; память backend; общий клиентский Refresh; горизонтальная полоса табов с прокруткой при переполнении и постоянно видимым `+`; Claude и агенты вне скоупа.

Defaults этого плана: `Tab N`, новый таб активен, выбор следующего/предыдущего после удаления, общий список. Они явно представлены здесь для ревью; переименование и drag-and-drop не добавляются.

## Risks / Trade-offs

- Одинаковое содержимое табов пока выглядит повторяющимся → это намеренно ограниченный текущий объём; не добавлять проектную навигацию ради демонстрации различий.
- Горизонтальная прокрутка требует изменения рендерера → добавить только необязательное свойство row и проверить ограничение ширины, отсутствие регрессий обычных row и доступность `+` при переполнении.
- Старые тесты предполагают одинаковый startup в обоих режимах → разделить ожидания; сохранить существующие проверки directory-компонента и log-only действий.
- Вложенные внутренние события могут обойти старую проверку decode → покрыть отказ на подделанный directory-load результат через новый wrapper.
- Совместные будущие изменения Home с `claude-agent-chat` → разрешать конфликт при реализации того change; этот план не требует его выполнения.

## Migration Plan

Обновить Android-клиент с поддержкой `horizontalScroll`, затем backend и README. Новый клиент сохраняет поведение старых документов без поля; старый клиент не обеспечивает прокрутку новой полосы, поэтому обновление только backend недостаточно. Нет миграции данных: табы эфемерны, перезапуск сбрасывает их. Откат backend возвращает прежний стартовый экран; каталоги и история агентов не изменяются.

Проверить TEA-переходы, сериализацию и HTTP-документы в `test/test_remote_dev.ml`, выполнить `dune test`, `dune build`, `dune fmt` и host-сборку Android. В `BackendUiParserTest.kt` добавить проверки нового свойства row и горизонтального overflow с фиксированным `+`. Instrumentation и визуальную проверку пустого состояния, нескольких табов, горизонтальной прокрутки, переключения, удаления и общего Refresh выполнять только на разрешённом устройстве `abf51f11`; если оно недоступно, пропустить только device-проверки и сообщить это.
