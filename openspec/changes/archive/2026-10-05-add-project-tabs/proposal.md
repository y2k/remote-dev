# Proposal

## Why

Нужны управляемые пользователем табы как первый шаг к работе с несколькими проектами. Сейчас backend хранит один экран; ближайший объём — только создание, переключение и удаление табов, каждый из которых показывает существующий список проектов.

## What Changes

- В OpenCode-режиме запускать UI с нулём табов, кнопкой `+` и общей панелью эмулятора.
- Добавить создание, выбор и удаление табов, включая последний. Сохранять их только в памяти backend; перезапуск начинает с нуля.
- Расположить табы одной горизонтальной полосой над списком проектов. При переполнении полоса прокручивается по горизонтали; кнопка `+` остаётся видимой вне прокручиваемой области.
- В каждом открытом табе показывать существующий список директорий стартового корня. Клик по проекту продолжает только логировать путь.
- Использовать общий клиентский `Refresh` и возврат полного UI-документа; клиент не знает о табах. Перезагрузка UI сохраняет табы и выбор.
- Предлагаемые минимальные defaults: имена `Tab N`, активация нового таба, выбор соседа после удаления активного. Данные одинакового списка проектов общие для табов, без отдельного устаревающего кеша на каждый таб.

## Capabilities

### New Capabilities

- `project-tabs`: жизненный цикл табов, пустое состояние, выбор, общий список проектов и backend-defined UI.

### Modified Capabilities

- `startup-directory-list`: в OpenCode список отображается внутри таба, а не сразу при запуске; общий Refresh перечитывает общий список при наличии табов.
- `eio-http-server`: начальное состояние OpenCode содержит ноль табов; HTTP-перезагрузка сохраняет состояние в памяти.
- `opencode-session-attachment`: начальная оболочка OpenCode — табы, а не непосредственно список директорий; подключения к агенту для неё не требуется.
- `startup-agent-mode`: запуск OpenCode без доступного сервера отображает пустую оболочку табов.

## Impact

- Backend: `lib/home.ml`, `lib/home_components.ml`, `lib/server.ml`, `lib/components.ml`; переиспользуются TEA, `Directories` и существующие UI-узлы, row получает необязательный признак горизонтальной прокрутки. Новые зависимости не нужны.
- Android: универсальная поддержка горизонтально прокручиваемого row в `MainActivity.kt` и `UiNodeContent.kt`, без клиентской модели табов. Проверки: `test/test_remote_dev.ml` и `android/app/src/androidTest/java/io/y2k/remote_client/BackendUiParserTest.kt`; документация: `README.md`.
- Сессии, чаты, выполнение агентов, сохранение на диск, переименование и перестановка табов не входят в изменение. Claude вне скоупа; change не зависит от заблокированного `claude-agent-chat`.
