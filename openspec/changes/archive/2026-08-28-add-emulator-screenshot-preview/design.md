## Context

См. `proposal.md` и delta specs. Текущий backend отдаёт один JSON UI-документ, а Android принимает только `column`, `row`, `text`, `button` и `input`. `Worktree` уже является контекстом для Claude-команд; отдельный экран эмуляторов потребовал бы новой навигации и менял бы существующую Back-семантику. Runtime уже запускает локальные процессы через аргументы, а сервер пока обслуживает только `/`.

## Goals / Non-Goals

**Goals:**
- Оставить выбор эмулятора обычным backend event и показывать снимок на существующем экране worktree.
- Добавить ровно один общий SDUI node `image` с backend-relative `src` и `label`.
- Загружать PNG отдельно от UI event и без новой Android-зависимости.
- Не выполнять ADB-команду с serial, который не подтверждён как запущенный эмулятор.

**Non-Goals:**
- Не добавлять отдельный экран, видеопоток, запись экрана, управление эмулятором или предпросмотр физических Android-устройств.
- Не кэшировать снимки на сервере и не делать фоновый захват всех эмуляторов.
- Не менять общий HTTP event envelope, навигацию или формат существующих node.

## Decisions

### Preview remains inside `Worktree`

Модель `Worktree` хранит загруженный список эмуляторов и выбранный serial. При входе в worktree command загружает подключённые ADB serial с префиксом `emulator-`, получает имя AVD для каждого и выбирает первый доступный. `Loaded_emulators` обновляет модель, а `Select_emulator` меняет только выбранный serial. View строит кнопки из уже существующего `button` и один `image`; при пустом списке выводит текст.

Это использует уже существующий экран и системный Back. Отдельный `Home.screen` отклонён: он потребует хранить исходный worktree для возврата и добавит навигационный поток только ради одного блока.

### `image` is a small, backend-relative SDUI node

`Components` получает node с полями `src` и `label`. Serializer публикует `{ "@type": "image", "src": ..., "label": ... }`; `map` оставляет node неизменным. Backend формирует `src` только как путь `/emulators/<serial>/screenshot.png` для serial из текущей модели.

Android parser принимает только backend-relative путь, начинающийся с одного `/`, и соединяет его с уже настроенным backend origin. Это не позволяет SDUI-документу направить клиент к произвольному host. Выбрано общее `image`, а не node `emulator_screenshot`: изображения остаются единственным расширением протокола, а эмуляторная доменная логика остаётся в backend view.

### Screenshot endpoint captures on demand

Сервер обслуживает `GET /emulators/<serial>/screenshot.png`. Перед запуском ADB он повторно сверяет serial со списком работающих `emulator-*`; неизвестный или исчезнувший serial получает non-success response. Для допустимого serial backend запускает `adb -s <serial> exec-out screencap -p`, передаёт его байты как `image/png` и устанавливает `Cache-Control: no-store`.

Runtime добавляет минимальную binary-вариацию существующего process runner для вывода `screencap`; список устройств и имя AVD остаются line-oriented командами. Capture выполняется вне network fiber через существующий `domain_mgr`, чтобы блокирующее чтение PNG не задерживало другие HTTP-запросы. Аргументы процесса передаются как argv, а не через shell.

Серверный кэш отвергнут: один локальный клиент делает один запрос раз в три секунды, а on-demand capture проще и гарантирует свежий кадр. Кэш нужен только при измеренной нагрузке от нескольких клиентов.

### Android refreshes only the image

`UiNode.Image` рендерится Compose `Image` с сохранением пропорций. Composable запускает запрос PNG при появлении и затем каждые три секунды, отменяя предыдущий цикл при смене `src` или удалении node. Ответ декодируется в bitmap штатными Android API; сетевой запрос использует существующий Ktor client. Ошибка показывает `label` и не меняет `ScreenState`, поэтому кнопки и input вокруг preview остаются активными.

Периодический `POST /` или streaming UI document отклонён: он обновлял бы весь экран, конфликтовал бы с единственным event request и создавал бы ненужную нагрузку на Home state.

## Risks / Trade-offs

- [ADB недоступен, эмулятор остановлен или `screencap` завершается ошибкой] → endpoint отвечает ошибкой, а Android показывает ошибку только внутри `image`.
- [Serial исчезает между построением документа и PNG request] → endpoint повторно проверяет доступность и не запускает capture для неизвестного serial.
- [PNG велик или capture медленный] → один выбранный эмулятор обновляется не чаще раза в три секунды и capture выполняется вне network fiber; добавить сжатие или server cache только после измерения.
- [Старый Android-клиент не знает `image`] → сервер и Android-клиент выпускаются вместе; rollback возвращает обе стороны к предыдущей версии.

## Migration Plan

1. Выпустить backend и Android-клиент вместе, поскольку новый worktree-документ содержит `image`.
2. Проверить список из нескольких AVD, отсутствие AVD, смену выбранного эмулятора и обновление PNG через три секунды.
3. При rollback вернуть backend и Android-клиент к предыдущим версиям; сохранённых данных и миграций состояния нет.
