# Design

## Context

Мотивация описана в `proposal.md`. Сейчас `Project_tabs` хранит только список числовых идентификаторов и общий `Directories.model`. `Home` отдельно содержит экраны `Sessions` и `Session`, но перехода к ним из вкладок нет. `Sessions` запрашивает общие последние 20 сессий через `Runtime.load_opencode_sessions`; создание отсутствует.

`Session` уже реализует переписку, промпт, голосовой черновик, Stop и ошибки. В `Server` отдельно распознаются обычные промпты и фоновые slash-команды, причём только в корневой форме `Home.Session_msg`. Декодер запрещает клиентам присылать внутренние результаты. Эти маршруты необходимо адаптировать вместе с навигацией.

UI определяется OCaml backend; Android отображает стандартные узлы и передаёт opaque events. Проверки используют `Runtime.with_http` и подставные ответы, поэтому основные тесты не требуют устройства или работающего OpenCode.

## Goals / Non-Goals

**Goals:**
- Переиспользовать существующие TEA-компоненты `Directories`, `Sessions` и `Session`, сохранив чистый `view` и эффекты через `Cmd`.
- Хранить контекст навигации и направлять результаты операций в соответствующую вкладку.
- Добавить минимальные операции чтения сессий папки и создания сессии в существующий HTTP-слой.

**Non-Goals:**
- Новые Android Activity, модальные окна, клиентский router или новые UI-примитивы.
- Постоянное хранение вкладок, автоматическое обновление чатов, пагинация в интерфейсе, переименование вкладок, выбор модели/агента при создании.
- Миграция всей интеграции OpenCode на другую версию API, рекурсивный поиск папок и группировка worktree.

## Decisions

### 1. Экран принадлежит вкладке

Дополнить запись вкладки собственным состоянием: `Directories`, `Sessions` либо `Session` с сохранённой моделью списка. Общий `Directories.model` остаётся в `Project_tabs`; состояние сессий относится к конкретной вкладке. `Home` продолжает владеть общим эмулятором и делегирует Back/Refresh активной вкладке.

```text
Home
  +-- Project_tabs
  |     +-- shared directories
  |     +-- Tab 1: Directories --> Sessions(folder) --> Session
  |     |                    <--                  <--
  |     +-- Tab 2: own screen
  +-- shared emulator
```

Перенести определение `Project_tabs` ниже используемых компонентов в `home_components.ml`, если этого потребуют зависимости OCaml. Отдельный универсальный стек навигации не нужен: достаточно трёх вариантов состояния. Альтернатива с переключением корневого `Home.screen` теряет вкладки и не сохраняет независимые чаты.

### 2. Адресованные события и результаты

События содержимого должны нести стабильный ID вкладки. Команды отображаются через `Cmd.map` обратно в тот же контекст; ответы дополнительно сопоставляются с текущим экраном и его папкой/сессией. При необходимости идентификатор поколения экрана отличает поздний результат от повторного открытия той же папки. Закрытая вкладка не восстанавливается по результату команды.

В `server.ml` извлекать адресованную сессию из вложенного события для обычного промпта и slash-команды. В контексте фоновой команды сохранять ID вкладки и сессии, а завершение направлять туда же. Сохранить текущий быстрый JSON-ответ на принятие обычного промпта и запуск slash-команды; прочие конечные загрузки используют существующий NDJSON-путь. Внутренние результаты, включая создание сессии, запрещены декодером на всех новых уровнях вложенности.

Маршрутизация по текущей активной вкладке проще только внешне: она переносит ошибки и результаты фоновой работы в чужой чат. Поэтому явный адрес — необходимая часть изменения.

### 3. Фильтрация до ограничения списка

`Sessions.model` хранит выбранный абсолютный путь, результаты, состояние загрузки/ошибку. Готовая `Runtime.load_opencode_folder_sessions` принимает папку. Предел 20 и порядок по времени последнего обновления применяются сервером после точного отбора по директории; подпапки и другие worktree исключены.

Проверенный V2-запрос: `GET /api/session?limit=20&order=desc&directory=<encoded path>`, ответ `{data:[Session.Info],cursor:{...}}`. Используется одна страница. Статусы берутся из общей `/api/session/active`, дополнительные retry-детали запрашиваются только для отображаемых активных сессий.

Миграция `401b293` уже реализовала контракт V2; источник проверки — `docs/handoff-opencode-v2-runtime.md`, схема/исходники 2.0.24 и read-only проверка сервиса 2.0.25. Каждая операция обнаруживает уже запущенный сервис через `$XDG_STATE_HOME/opencode/service.json` (по умолчанию `~/.local/state/opencode/service.json`) и проверяет `/api/info`. Basic authentication использует username `opencode` и password регистрации, включая пустой; отсутствующий password исключает заголовок. Переменные пароля backend не переопределяют регистрацию. Повторная миграция и новые runtime-абстракции не нужны.

### 4. Создание без формы

В `Sessions.view` над прокручиваемыми строками разместить путь папки и кнопку «Создать новую сессию». Новое сообщение вызывает готовую `Runtime.create_opencode_session`: `POST /api/session` с `{location:{directory}}`, HTTP 200 и `{data:Session.Info}`. Сохраняется ID из ответа. Отсутствующие title/agent/model допустимы; runtime отображает «Без названия» и сохраняет `None` для агента/модели. Клиент не выбирает defaults и не отправляет устаревшую конфигурацию в последующих промптах. Подключение и authentication делегированы runtime.

Успешный ответ добавляет возвращённую сессию в начало сохранённого списка с ограничением 20 и открывает переиспользуемый `Session` с пустой перепиской и полем ввода. Промпт автоматически не отправляется. Если последующая загрузка деталей не удалась, оставаться в уже созданном чате с ошибкой, не повторять создание. Ошибка самого создания оставляет пользователя в списке с возможностью явного повтора. Пока запрос создания выполняется, повторное действие не запускает второй запрос.

Альтернатива с формой имени добавляет несогласованный шаг; отдельный собственный объект «черновик сессии» не нужен.

### 5. Навигация и обновление

При выборе папки проверить её наличие в общем списке и загрузить сессии в той же вкладке. При выборе строки использовать найденную серверную запись, включая её directory/workspace, вместо пути или ID из произвольного клиентского payload.

Back из чата возвращает сохранённый список, включая только что созданную сессию; Back из списка возвращает общий список папок без чтения диска. Повторное открытие папки и явный Refresh заново читают сессии. Refresh чата использует текущую загрузку transcript/status/pending input; отсутствие сессии возвращает к её папке с существующим сообщением об ошибке. Переключение вкладок ничего не загружает. Состояние другой вкладки с той же сессией обновится при её собственном Refresh.

Пустой список показывается после успешного пустого ответа, а не вместо ошибки первоначальной загрузки. Ошибка refresh сохраняет последнюю успешную выборку. Поведение папок в Claude остаётся с логированием.

## Risks / Trade-offs

- Миграция и UI-change меняют одно требование списка → при sync сначала применить `migrate-opencode-v2-api`, затем этот change, сохранив V2 active-map и authentication.
- Глобальная страница вместо выборки папки → тест с более чем 20 новыми сессиями других папок и более старой подходящей сессией.
- Фоновый ответ после переключения/закрытия → адресация по вкладке и экрану; тесты переключения, удаления и позднего результата.
- Повтор создания после сетевой ошибки может создать вторую сессию, если первый запрос уже принят → не повторять автоматически; пользователь может сначала обновить список. Серверную идемпотентность не изобретать.
- Несколько вкладок одной сессии имеют разные снимки → сохраняется ручной Refresh без дополнительной синхронизации.
- Предел 20 означает отсутствие старой истории в этом интерфейсе → предел унаследован; история остаётся в OpenCode.

## Migration Plan

1. Проверить контракт совместимого OpenCode и реализовать runtime, компоненты, маршрутизацию и регрессионные тесты.
2. Обновить README: новый путь навигации, фильтрация папки, создание, Back и Refresh.
3. Выполнить `dune fmt`, `dune build`, `dune test`; затем при наличии разрешённого устройства проверить интерфейс.
4. Развернуть backend; существующий Android renderer использует уже поддерживаемые узлы. Перезагрузка backend очищает временные вкладки как и раньше.
5. Откатить backend при необходимости. Созданные сессии остаются в OpenCode и не удаляются откатом.
