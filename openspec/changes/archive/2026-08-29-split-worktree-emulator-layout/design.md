## Context

См. `proposal.md` и delta specs. Сейчас `Worktree.view` строит одну вертикальную `column`, где `Emulator.view` расположен между path и Claude-контентом. Backend SDUI имеет только `row` без sizing metadata, а Android Compose рендерит его детей по размеру содержимого. Поэтому перестановка детей в backend не может гарантировать пропорцию 2:1.

`Emulator` уже является самостоятельным TEA-компонентом, и его model/update менять не требуется. Android уже использует Compose `Row`, `Column` и штатные modifier-ы; новая зависимость для раскладки не нужна.

## Goals / Non-Goals

**Goals:**
- Выразить пропорциональную горизонтальную раскладку в существующем server-defined UI, не в клиентском special-case для эмулятора.
- Сохранить существующее поведение всех `row`, которые не запрашивают веса.
- Переместить `Emulator.view` целиком, не разделяя его заголовок, selector, image и состояния ошибки или отсутствия устройств.

**Non-Goals:**
- Не менять `Emulator.model`, messages, загрузку ADB или screenshot refresh.
- Не добавлять adaptive breakpoint, вертикальную раскладку для узких экранов или пользовательское изменение ширины панелей.
- Не делать правую панель sticky и не вводить независимую прокрутку: обе панели остаются частью существующей общей прокрутки экрана.
- Не обобщать sizing на `column`, поскольку текущему требованию нужен только горизонтальный split.

## Decisions

### `row` получает необязательные веса

OCaml-вариант `Row` будет хранить существующий список детей и необязательный список целочисленных весов. Helper `row` получит необязательный аргумент, поэтому существующие вызовы останутся без изменений. `Components.map` сохранит веса при подъёме events, а `to_json` добавит `"weights"` только для weighted row.

Отдельный node `split_pane` отклонён: он дублировал бы уже существующую горизонтальную композицию и добавлял новый parser branch ради одного свойства. Generic wrapper с weight также отклонён: Compose weight имеет смысл только внутри конкретного `Row`, поэтому metadata проще и однозначнее принадлежит родительской раскладке.

### Android валидирует и применяет веса на уровне `Row`

`UiNode.Row` получит nullable список числовых весов. Parser примет `weights` только как массив той же длины, что `children`, где каждый элемент является положительным числом; нарушение делает весь документ некорректным, как и другие ошибки SDUI.

Если веса отсутствуют, текущий Compose `Row` и content-sized children сохраняются. Если веса присутствуют, `Row` заполняет доступную ширину, а каждый child рендерится внутри минимального `Box` с `Modifier.weight`; это локализует Compose-specific sizing и не требует протягивать `Modifier` через все варианты `UiNodeContent`.

Клиентское распознавание emulator `image` или позиции child отклонено: Android не должен знать доменную семантику backend tree, а любое такое правило сделало бы layout зависимым от случайной структуры документа.

### Worktree становится weighted row из двух цельных панелей

`Worktree.view` продолжит вычислять список Claude messages, затем соберёт левую `column` из заголовка, path, output, shortcuts и command input. Вторым ребёнком будет существующий mapped `Emulator.view`. Внешний `row` получит веса `[2; 1]`, поэтому порядок дерева одновременно задаёт левую и правую стороны.

Ошибка верхнего уровня worktree останется обёрткой над этим content, как сейчас. Ошибка или пустое состояние самого `Emulator` остаются внутри второго child, поэтому split не исчезает при смене состояния.

Перенос sizing в Android screen code отклонён: root renderer не знает, какой документ является worktree, и не должен разбирать backend events или текст для определения панелей.

### Проверки покрывают протокол и итоговую композицию

OCaml-проверка сериализации подтвердит, что weighted row публикует `weights`, а обычный row их не публикует. Проверка worktree document подтвердит верхний row с `[2, 1]`, основным контентом первым и emulator image или его состоянием вторым.

Android contract tests покроют разбор weighted и unweighted row, а также отклонение неверной длины, типа и неположительных значений. Compose-проверка сравнит ширины двух weighted children и подтвердит отношение 2:1; существующие проверки image refresh и input events должны остаться без изменений поведения.

## Risks / Trade-offs

- [Длинный path, output или label не помещается в левую панель] -> Сохранять пропорцию 2:1 и полагаться на стандартное измерение/перенос Compose; отдельные правила overflow добавлять только по воспроизведённой проблеме.
- [Горизонтальный split тесен на телефоне в portrait] -> Это прямое требование фиксированной пропорции; adaptive breakpoint потребует отдельного продуктового решения.
- [Неверные веса от backend могут сломать измерение Compose] -> Валидировать число, положительность и соответствие количеству детей до создания `UiNode.Row`.
- [Активный change `dispatch-input-handlers` затрагивает `components.ml`, `home_components.ml` и тесты] -> При apply сохранить его актуальные изменения и ограничить этот change формой `Row` и композицией `Worktree.view`.

## Migration Plan

1. Добавить поддержку необязательных весов в backend SDUI и Android parser/renderer.
2. Переключить только worktree document на weighted row `[2, 1]` и выполнить OCaml и Android проверки.
3. Выпустить backend и Android-клиент вместе: старый клиент проигнорирует `weights` и не обеспечит требуемую пропорцию.
4. Для rollback вернуть worktree к прежней column и удалить weights из документа; сохранённых данных и миграций состояния нет.
