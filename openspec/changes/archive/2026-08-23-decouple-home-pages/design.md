## Context

См. motivation в `proposal.md`. Сейчас `Worktrees.update` и `Worktree.update` возвращают собственные типы `action`, а `Home` сопоставляет их конкретные конструкторы. Глобальный `decode` также создаёт конкретные дочерние сообщения и отправляет ошибки в текущую страницу. При возврате из worktree `Home` отдельно запускает `Worktrees.Load`, чтобы обновить список.

## Goals / Non-Goals

**Goals:**

- Оставить `Home` владельцем active screen и роутинга, но убрать из него знание о локальных сообщениях, ошибках и действиях страниц.
- Сохранить существующую синхронную модель `Cmd`, форму HTTP envelope и наблюдаемое поведение всех действующих событий.
- Сохранить перезагрузку списка worktree после `back` без того, чтобы `Home` посылал `Worktrees.Load`.

**Non-Goals:**

- Не вводить OCaml Tea dependency, GADT, first-class modules или универсальный page framework.
- Не менять HTTP routes, JSON UI document, Android-клиент или семантику команд.
- Не добавлять новые экраны, URL routing, асинхронность или persistence.

## Decisions

Определить небольшой общий `Route` с вариантами списка worktree и выбранного worktree с `path`. Это единственный результат перехода, который страницы публикуют наверх. Вместо отдельных `Worktrees.action` и `Worktree.action` их `update` возвращают `Route.t option`: `None` означает остаться на странице, `Some route` означает переход. `Home` сопоставляет только `Route`, а не конструкторы дочерних action.

Страницы сохраняют типизированные `msg` и дочерние `Cmd`; `Home` по-прежнему поднимает commands через `Cmd.map`. Это сохраняет текущую простую модель без циклической зависимости: страницы не должны знать `Home.msg`, а root не должен разбирать их конкретные сообщения.

Каждая страница получает локальный decoder для event types, допустимых на этой странице. Общий разбор JSON envelope остаётся общим, но после него `Home` делегирует активной странице. Неподходящее, но корректно сформированное событие становится page-local ошибкой или no-op согласно текущему поведению: `back` на списке не создаёт ошибку, `run_claude` без выбранного worktree создаёт существующую ошибку списка. Некорректный JSON по-прежнему даёт HTTP `Bad_request`.

Добавить к страницам lifecycle API для входа по `Route`. Вход в `Worktrees` создаёт начальную модель и запускает её локальную загрузку; вход в `Worktree` создаёт модель для переданного пути без команды. Поэтому после `back` именно роутер активирует список, а сама страница определяет, требуется ли загрузка. Альтернатива, при которой `Home` после маршрута явно отправляет `Worktrees.Load`, отклонена: она сохраняет утечку внутреннего сообщения.

`Home.update` делегирует только сообщение active page, поднимает вернувшуюся command и применяет optional `Route`. Несовпадающая пара active screen и внутреннего сообщения становится защитным no-op; внешний decoder и синхронные команды не должны её создавать. Альтернатива с error branch в `Home` отклонена, поскольку она вновь требует знать ошибочные состояния дочерних сообщений.

## Risks / Trade-offs

- [Page-local decoding повторит часть проверки JSON] → Вынести только разбор общего envelope; проверка event type остаётся рядом с page-local `msg`.
- [Вход страницы добавляет lifecycle API] → Ограничить API двумя текущими страницами и не создавать общий framework.
- [Несовпавшее внутреннее сообщение будет проигнорировано] → Внешний ввод маршрутизируется по active page, а все commands поднимаются из той же страницы; покрыть допустимые события регрессионными тестами.
- [Рефакторинг меняет границы, но не поведение] → Сохранить и обновить проверки для select, back, load, run и error cases.
