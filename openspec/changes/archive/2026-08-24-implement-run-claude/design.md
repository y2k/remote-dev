## Context

`Runtime.run_claude` сейчас имеет синхронную сигнатуру `string -> string`, модуль уже зависит от стандартной библиотеки `Unix`, а установленный Claude CLI поддерживает `--print` для non-interactive выполнения. Claude должен стартовать внутри выбранного worktree, но `Unix.open_process_args_in` не предоставляет отдельный параметр cwd. Путь и prompt могут содержать произвольный пользовательский текст, поэтому их интерполяция в shell-команду недопустима. Реализация ориентирована на текущую macOS/POSIX-среду с `/bin/sh`.

## Goals / Non-Goals

**Goals:**

- Расширить синхронную сигнатуру до `string -> string -> string`, принимая cwd перед prompt.
- Безопасно передать cwd и prompt и полностью прочитать stdout.
- Проверить статус завершения процесса.

**Non-Goals:**

- Streaming, отмена, timeout и управление Claude sessions.
- Захват или структурирование stderr.
- Подключение `run_claude` к HTTP-маршрутам и передача выбранного worktree через UI.
- HTTP trust boundary и управление persistence локальных Claude sessions.

## Decisions

Использовать `Unix.open_process_args_in` для запуска постоянного `/bin/sh` wrapper, который выполняет `cd "$1" && exec claude --print -- "$2"`. cwd и prompt передаются wrapper отдельными позиционными аргументами и раскрываются только внутри двойных кавычек, поэтому их содержимое не интерпретируется как shell-код; `--` не позволяет prompt с начальным дефисом стать CLI option. Временный `Unix.chdir` отклонён, потому что он изменяет cwd всего многопоточного серверного процесса; ручной `fork`/`pipe`/`exec` отклонён как лишняя сложность для синхронной функции.

Разрешать `claude` через унаследованный `PATH` и не переопределять обычные локальные settings, tools, hooks, MCP и permission mode. Не передавать `--dangerously-skip-permissions`: вызов получает настроенные возможности Claude CLI, но сохраняет его встроенные ограничения.

Прочитать stdout целиком через `In_channel.input_all`, затем закрыть процесс через `Unix.close_process_in`. Успешный status возвращает текст без дополнительного преобразования, любой другой status приводит к общему исключению без детализации exit status. Отдельный result type не вводится, чтобы сохранить простой синхронный контракт и соответствовать обработке ошибок в `Runtime.load_worktrees`.

stderr остаётся унаследованным процессом сервера. Это сохраняет диагностический вывод Claude CLI без дополнительного параллельного чтения каналов.

Изменить адаптер на `Home.test path body`, передавая оба значения в `Runtime.run_claude path body`. HTTP routing в этом change не добавлять.

## Risks / Trade-offs

- [Вызов блокирует обслуживающий fiber до завершения CLI] → Это соответствует текущей синхронной сигнатуре; асинхронное выполнение следует проектировать только вместе с HTTP-интеграцией.
- [Неограниченный stdout хранится в памяти] → Допустимо для одиночного локального prompt; лимит нужен, если функция станет публичной trust boundary.
- [stderr не возвращается вызывающему коду] → Он остаётся доступен в логах процесса; структурированный capture нужен только при появлении UI для ошибок.
- [Запуск зависит от `/bin/sh`] → Это штатная часть целевой POSIX-платформы; более сложное управление процессом потребует прямого `fork`/`exec`.
- [Claude наследует локально настроенные возможности] → Это намеренное поведение для локального инструмента; опасный обход permission checks не включается.
