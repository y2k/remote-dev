## Context

Мотивация описана в `proposal.md`. `Home` уже владеет глобальным `Emulator.model`, а `Home.Emulator_msg` маршрутизирует сообщения компонента независимо от текущего экрана. `Emulator.init` запускает существующий `load`; обработчик `Loaded` сейчас каждый раз выбирает первый serial либо очищает выбор. `view` скрывает весь selector, если выбора нет или выбранное устройство не найдено.

`Runtime.load_emulators` получает устройства через `adb devices -l` и имена через AVD-команду. Android уже отображает backend-defined кнопки и ответы NDJSON. Запросы скриншота проверяют доступность устройства, но не меняют модель списка.

Дизайн фиксирует семантику независимого выбора и границу между обновлением списка и запросами изображений, чтобы исчезновение устройства не трактовалось как команда сбросить выбор.

## Goals / Non-Goals

**Goals:** реализовать контракт delta-спецификации внутри существующего TEA-компонента с чистым `view`, сохранив текущие `model` и командный путь.

**Non-Goals:** фоновое обнаружение, автоперевыбор, сохранение на диск, идентификация по AVD name, новые Android-компоненты, изменение общего `Home.Refresh` или механизма обновления изображений.

## Decisions

### Локальное сообщение Refresh использует существующий load

Добавить `Emulator.Refresh`, возвращающий текущую модель и существующую команду `load`. Кнопка передаёт событие через уже имеющийся `Home.Emulator_msg`; результат `Loaded` обрабатывается обычным путём, а не bootstrap-сообщением `Initialize_emulator`, которое также инициализирует левую часть приложения.

Отдельная кнопка точнее соответствует запросу, чем расширение общего `Home.Refresh`, и не требует объединять команды разных панелей. Существующий транспорт уже возвращает UI после выполнения команды.

### Выбор — сохранённый serial, а не производное от списка

Оставить `selected_emulator : string option`. Успешный `Loaded` заменяет `emulators` и очищает ошибку, сохраняя текущий `selected_emulator` без проверки присутствия. Ошибка сохраняет список и выбор, как сейчас. `Select` по-прежнему принимает только serial из доступного списка.

`init` оставляет выбор `None`; только ручной `Select` меняет его. Не нужен отдельный флаг недоступности или сохранённая копия устройства: наличие выбранного serial вычисляется из списка в `view`.

### Selector и Refresh отображаются независимо от preview

Панель всегда строит заголовок, кнопку Refresh и кнопки доступных устройств. Затем чистый `view` выбирает содержимое preview:

| Выбор | Доступность | Preview |
|---|---|---|
| `None` | Список пуст | `No running emulators` |
| `None` | Есть устройства | `Select an emulator` |
| `Some serial` | Serial найден | Существующий `image` |
| `Some serial` | Serial отсутствует | `Selected emulator unavailable` |

Тексты предлагаются на английском в стиле текущего UI. Ошибка загрузки отображается дополнительно к содержимому панели и не прячет кнопку повтора. Другие устройства доступны для выбора даже при недоступном выбранном serial.

### Ручной Refresh определяет актуальность списка

Заглушка недоступности появляется после успешного Refresh, обнаружившего отсутствие serial. До него запрос скриншота может завершаться ошибкой по существующему контракту. Не связывать обнаружение со скриншотами: при первоначально пустом списке или отсутствии выбора `image` вообще не существует.

Возврат того же serial после Refresh восстанавливает preview через обычный поиск в списке, без повторного `Select` и без смены ID.

## Risks / Trade-offs

- [ADB serial может быть переиспользован другим AVD или измениться после перезапуска эмулятора] → Идентичность определяется именно serial; автоматического сопоставления по имени нет, пользователь выбирает другой serial вручную.
- [Пользователь видит устаревший список до нажатия Refresh] → Это явная граница ручного обновления; Refresh доступен во всех состояниях панели.
- [Старые проверки ожидают первоначальный автовыбор и сброс при пустом списке] → Обновить существующие assertions и явно выбирать устройство в сценариях, которым нужен preview; проверить сохранение ID при исчезновении и возвращении.

## Migration Plan

Изменение поставляется с backend; существующий Android renderer понимает необходимые кнопки, текст и изображения. После перезапуска backend список загружается, но preview появляется только после выбора пользователем. Миграции данных нет. Откат — возврат предыдущей реализации backend с прежним первоначальным автовыбором.
