## Context

См. `proposal.md`, раздел Why. В `lib/runtime.ml` все операции OpenCode проходят через `perform_http`, затем эффект `Http_request` и транспорт `request_http`. Сейчас заголовки содержат только контекст запроса, тип и длину тела и Host. `test/test_runtime.ml` уже перехватывает HTTP-эффекты и проверяет запросы без сетевого сервера.

`lib/dune` использует `eio`, `httpun`, `httpun-eio`, `unix`, `yojson`; готового Base64-помощника в проекте не найдено, `ocamlfind query base64` сообщает об отсутствии пакета. README описывает отдельный запуск OpenCode и backend. Существующая спецификация задаёт локальный адрес, но не определяет авторизацию; новый контракт дополняет её. Дизайн нужен для явного решения о передаче секрета через общий HTTP-путь.

## Goals / Non-Goals

**Goals:**
- Сформировать авторизацию один раз на общем пути каждого запроса, чтобы тесты проверяли те же заголовки, которые получает транспорт.
- Держать секрет исключительно в окружении и памяти backend, вне модели UI.

**Non-Goals:**
- Новые CLI-флаги, хранилище паролей, настройка авторизации через Android, изменение адреса сервера или авторизации провайдера модели.

## Decisions

1. **Добавлять заголовок в `perform_http` до `Http_request`.** Читать окружение через `Sys.getenv_opt` при формировании запроса. Это покрывает GET и POST, включая команды и abort, и использует существующий тестовый перехват. Альтернатива в каждом вызывающем методе дублирует логику; добавление только в транспорте скрывает заголовок от текущих проверок.

2. **Читать только пароль.** Непустой `OPENCODE_SERVER_PASSWORD` включает Basic Auth; отсутствующий или пустой пароль выключает его. По решению пользователя имя всегда равно `opencode`, переменные окружения для имени не читаются. Пароль не обрезается и не интерпретируется shell.

3. **Готовая библиотека для кодирования в памяти.** По решению пользователя подключить пакет `base64` и использовать `Base64.encode_exn` для байтов `username:password` со стандартным алфавитом, padding и без переноса строк. Зависимость объявляется в `dune-project` и `lib/dune`, opam-файл генерируется Dune. Собственный кодировщик и его алгоритмические тесты удаляются; проверки ожидаемого заголовка остаются. Это заменяет первоначальное решение о локальном кодировщике и уменьшает объём поддерживаемого кода.

4. **Не менять успешный протокол и не повторять 401 автоматически.** Сохранять путь отображения HTTP-ошибки; для 401 выводить статус без тела ответа, чтобы сервер не мог отразить авторизационные данные в UI. Не логировать заголовок или пароль. Транспорт остаётся фиксированным loopback-соединением и не выполняет перенаправления.

5. **Проверки в существующем тесте.** Через перехват `Http_request` проверить отсутствие/пустоту пароля, постоянное имя `opencode` независимо от окружения и заголовок в запросах чтения и записи. Изолировать изменения окружения и восстанавливать его после проверок; реальные секреты не использовать. Для 401 проверить сообщение без отражённого секрета.

## Risks / Trade-offs

- Пароль задан только процессу OpenCode → README должен явно объяснить, что backend наследует те же переменные при своём запуске, в том числе из другого терминала.
- Зависимость от пакета `base64` → объявить пакет в сборке и сохранить проверки полного ожидаемого заголовка.
- Basic Auth не шифрует секрет → сохраняется соединение только с фиксированным `127.0.0.1:4096`; настройка удалённого адреса не входит в изменение.

## Migration Plan

Собрать backend, передать ему те же переменные окружения, что серверу OpenCode, и перезапустить backend. Для проверки использовать загрузку списка сессий; пароль в вывод не включать. Миграции данных нет. Откат — возврат предыдущей сборки, которая снова не поддерживает защищённый сервер.
