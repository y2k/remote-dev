# Design

## Context

См. `proposal.md`, раздел Why. В `lib/home_components.ml` функция `Sessions.view` возвращает колонку с весами `[0; 0; 0; 1]`: ошибки, заголовок, путь с кнопкой, список карточек. В `android/app/src/main/java/io/y2k/remote_client/UiNodeContent.kt` положительный вес ребёнка колонки включает `verticalScroll`. Поэтому сейчас прокручиваются только карточки.

Этот документ фиксирует границу прокрутки и положение индикатора создания, которые короткий запрос не детализирует.

## Goals / Non-Goals

**Goals:**
- Использовать существующую прокрутку через серверное дерево UI и сохранить TEA-компонент `Sessions` с чистой `view`.
- Поместить кнопку и её состояние ожидания в один поток с карточками.

**Non-Goals:**
- Изменять модель, сообщения, обработчик создания, runtime, протокол UI или Android renderer.
- Вводить отдельный scroll state, вложенную прокрутку или закреплённую копию кнопки.

## Decisions

### Переместить только управляющий элемент в существующую weighted column

В блоке с нулевым весом оставить путь. В начало списка детей последней колонки добавить кнопку `Create` либо текст `Creating session...`, только когда `directory` задана. После них оставить текущие карточки или состояние списка. Сохранить существующие отступы и `gap` этой колонки.

Допущение: пользователь просит прокручивать именно кнопку; путь, заголовок и ошибки остаются в текущих областях. Альтернатива — переносить весь заголовок — расширяет изменение без необходимости. Изменять renderer также не требуется: он уже реализует нужную прокрутку.

Действующее требование «above its rows» совместимо с новым положением: кнопка остаётся перед карточками, но больше не закреплена. Delta уточняет это поведение и сохраняет все прежние сценарии создания.

### Проверять поведение существующими средствами

Выполнить `dune fmt`, `dune build`, `dune test`; существующий `test/test_folder_tabs.ml` проверяет события создания, ошибки и возврат. Для небольшой перестановки UI отдельный структурный тест, повторяющий дерево, не нужен. На устройстве проверить длинный список: кнопка уходит за верхнюю границу и возвращается при прокрутке к началу. Дополнительно проверить пустой список, ошибку загрузки и создание с возвратом. Уточнить прокручиваемое положение кнопки в `README.md`.

## Risks / Trade-offs

- [Кнопка недоступна непосредственно внизу длинного списка] → это целевое поведение; возврат к началу снова показывает её.
- [Кнопка либо индикатор случайно останутся в старом блоке] → проверить оба состояния дерева и визуально подтвердить общий поток с карточками.
- [Устройство недоступно] → выполнять host-side проверки независимо; device-проверки проводить только на `abf51f11`, предварительно задав `ANDROID_SERIAL=abf51f11`, иначе отметить их невыполненными.
