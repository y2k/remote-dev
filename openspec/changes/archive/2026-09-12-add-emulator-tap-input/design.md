## Context

Мотивация описана в `proposal.md`. Изменение затрагивает общий UI-узел, Android-рендерер и OCaml-компонент, поэтому требует общего описания протокола.

- `Components.Image` сейчас хранит только `src` и `label`.
- `ImageContent` показывает bitmap через `ContentScale.Fit`; `LaunchedEffect(node.src)` загружает PNG и повторяет запрос после трёхсекундной паузы. Получение нового UI-документа с прежним `src` само по себе не обновляет изображение.
- `MainActivity.kt` отправляет непрозрачный массив `event` и строку либо `null` в `value`; сервер заменяет `__VALUE__` этой строкой. UI-запросы сериализованы общей блокировкой.
- `Home_components.Emulator` уже содержит selection, список устройств и поле ошибки, а побочные эффекты выполняет через `Cmd`. Runtime использует ADB и типизированный список аргументов процесса.
- Есть прежнее расхождение документации: основная спецификация `android-backend-driven-ui` называет события кнопок/полей объектами, но парсер, OCaml-кодеки, тесты и README используют массивы. Новое событие изображения явно использует фактический формат массива; изменение формата существующих событий не требуется.

## Goals / Non-Goals

**Goals:**
- Переиспользовать общий UI event envelope, отправку строкового значения и существующий TEA-компонент без специализированного сетевого канала.
- Связать координаты с показанным bitmap, а serial — с серверным событием именно этого превью.

**Non-Goals:**
- Протокол непрерывного ввода, параллельное управление во время других UI-запросов, подтверждение кадра или синхронизация с анимациями.
- Обобщение `value` до произвольного JSON и реформа существующего протокола событий.

## Decisions

### 1. Необязательный event у существующего image

Расширить `Components.Image`, `image`, `map` и `to_json` необязательным событием; Android-модель и парсер повторяют существующий подход кнопок. `Emulator.view` задаёт событие вида `Tap (serial, "__VALUE__")`. Корневой `Components.map` оборачивает его в `Emulator_msg`, как уже делает для выбора устройства.

Пример отправленного envelope:

```json
{
  "event": ["Emulator_msg", ["Tap", "emulator-5554", "__VALUE__"]],
  "value": "{\"x\":540,\"y\":960,\"width\":1080,\"height\":1920}"
}
```

Клиент сохраняет event неизменным, а JSON координат передаёт через существующий callback отправки строкового значения. Декодирование payload выполняется на бэкенде существующими JSON-средствами. Имена полей — выбранная техническая договорённость, не дополнительная пользовательская функция.

Альтернатива — объект в `value` — потребовала бы изменения общего envelope и замены маркеров. Отдельный endpoint потребовал бы второго пути отправки и обработки ошибок. Для одного тапа оба варианта избыточны.

### 2. Перевод координат на клиенте

Распознавать завершённый одиночный тап средствами Compose на загруженном изображении. Использовать фактический размер layout и текущего bitmap. При центрированном `Fit`:

```text
s = min(layoutWidth / bitmapWidth, layoutHeight / bitmapHeight)
left = (layoutWidth - bitmapWidth * s) / 2
top  = (layoutHeight - bitmapHeight * s) / 2
x = floor((tapX - left) / s)
y = floor((tapY - top) / s)
```

Сначала проверять попадание в нарисованный прямоугольник с исключёнными правой и нижней границами; затем ограничить результат допустимым последним пикселем на случай погрешности float. Размеры и точка берутся из одного показанного bitmap. Пустые поля не превращать в нажатия на край экрана. Обработчик использует актуальные event, bitmap и `eventInProgress`, а не значения от предыдущего выбора или загрузки. Сохранить `contentDescription`.

Альтернатива — нормализованные координаты с запросом размера экрана на сервере — добавляет ADB-запрос, хотя исходные размеры уже известны клиенту.

### 3. Ввод остаётся командой TEA-компонента

`Emulator.update` проверяет JSON payload: обязательные целочисленные поля, положительные размеры и координаты внутри переданных границ. Serial должен совпадать с выбранным и присутствовать в последнем успешно загруженном списке. Некорректные данные показывают ошибку; устаревший serial игнорируется без команды. Неизвестный serial нельзя напрямую передавать в ADB.

Для допустимого запроса вернуть `Cmd.Run`, который вызывает небольшой runtime helper с аргументами `adb -s <serial> shell input tap <x> <y>`. Координаты сериализуются из проверенных целых чисел; произвольная строка payload не попадает в shell. Использовать существующий механизм process effects и проверять exit status.

Завершение возвращает внутреннее сообщение результата. Оно обновляет поле ошибки панели, сохраняет screen, selection и список; успешный тап очищает предыдущую ошибку ввода. Внешний запрос не должен иметь возможности подделать новое внутреннее сообщение завершения: добавить его в существующее отклонение внутренних сообщений в `Server.decode`. Повторное получение списка не требуется: остановившееся устройство обнаруживается по ошибке команды.

Альтернатива — выполнять ADB непосредственно в HTTP-route — дублирует обработку состояния и обходит уже существующий компонент.

### 4. Текущая сериализация и таймер сохраняются

Обработчик изображения использует текущий `eventInProgress`; заблокированные тапы не ставятся в очередь. Результат команды возвращается существующим механизмом UI-документов, включая NDJSON для `Cmd.Run`. `src` не получает версии или cache-busting параметра после тапа. Цикл скриншотов остаётся привязан к прежнему `src` и не получает сигнала внеплановой загрузки.

## Risks / Trade-offs

- [Старый кадр и задержка обратной связи] → Пользователь принял текущий трёхсекундный polling. Тап выполняется по показанным координатам без гарантии, что содержимое экрана осталось прежним.
- [Поворот или изменение разрешения между кадром и тапом] → Не вводить frame-id, серверное хранение PNG или запрос геометрии на каждый тап. Размеры payload описывают показанный кадр, а не удостоверяют текущее состояние устройства. Отметить ограничение комментарием `ponytail:`; пересмотреть, если потребуется управление при смене ориентации.
- [Долгая операция агента блокирует ввод] → Сохранить существующую блокировку, как согласовано; отдельная очередь или канал сейчас не нужны.
- [Ошибка ADB] → Показать в существующей панели, завершить запрос и разрешить повторную попытку без автоматического повтора тапа.
- [Регрессии масштаба и polling] → Проверить преобразование при разных пропорциях и margin, блокировку, точный ADB argv, отклонение неправильных данных и отсутствие дополнительной загрузки после ответа.

## Migration Plan

Собрать и обновить клиент и бэкенд вместе. Изображения без event продолжают работать, структура envelope остаётся прежней. Хранилища и миграции данных отсутствуют. Для отката вернуть предыдущие сборки клиента и бэкенда.
