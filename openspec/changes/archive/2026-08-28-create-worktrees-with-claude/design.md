## Context

См. `proposal.md`. Текущая форма `New_worktree` получает имя, но её update возвращает `Cmd.none`; `Runtime` умеет запускать команды через `Args`, а список worktree уже загружается отдельной командой. Локальный Claude CLI поддерживает `--worktree [name]`, создающий worktree для сессии.

## Goals / Non-Goals

**Goals:**
- Создавать worktree без поля пути в Android UI.
- Вернуть пользователя к актуальному списку только после успешного завершения создания.
- Не допускать shell-интерполяции имени worktree.

**Non-Goals:**
- Выбор пути, начальной ревизии или существующей ветки.
- Долгоживущая Claude-сессия, отображение её ответа или запуск пользовательского prompt.
- Перехват stderr Claude CLI.

## Decisions

Создание запускает Claude из корня репозитория с `--worktree <name>` и `--print`, коротким фиксированным prompt и отключёнными инструментами. Процесс завершается после одного ответа, а созданный worktree остаётся в Git. Это использует нативный механизм Claude для выбора пути и не требует отдельного соглашения об именовании директорий. Альтернатива с `git worktree add` отклонена: она потребует определить путь в UI или в новой локальной конвенции.

Имя передаётся процессу через `Runtime.Args`, а не через shell. Пустое значение отклоняется до запуска, поскольку у `--worktree` имя опционально и пустое поле могло бы создать worktree с непредсказуемым именем. Проверку остальных ограничений имени делегировать Claude CLI и Git.

Успешное завершение создания переводит Home к сохранённой модели списка и запускает её существующую загрузку. Ошибка оставляет форму открытой и заполняет её уже существующее поле `error`. Альтернатива с оптимистическим добавлением worktree в сохранённую модель отклонена: фактический путь выбирает Claude CLI, а `git worktree list` уже является источником истины.

## Risks / Trade-offs

- [Создание выполняет один запрос Claude и зависит от его доступности] → ограничить сессию одним фиксированным prompt и отображать ошибку запуска.
- [CLI может изменить соглашение об имени или расположении worktree] → после успеха получать путь только через `git worktree list`.
- [Текст ошибки Git остаётся в stderr процесса] → UI показывает ошибку завершения; захват stderr добавить только при необходимости диагностировать реальные сбои.
