## Context

См. `proposal.md` для мотивации. Кнопки выбранного worktree уже отображаются в backend-документе, но не содержат событий. `Command2` получает начальный текст только из следующего backend-документа, поэтому выбранный prompt должен входить в in-memory состояние страницы.

## Goals / Non-Goals

**Goals:**

- Передать нажатие каждой shortcut-кнопки через существующий JSON event envelope.
- Вернуть тот же экран worktree с заменённым значением `Command2`.

**Non-Goals:**

- Изменять Android-рендеринг, HTTP transport или `Runtime.run_claude`.
- Выполнять Claude при выборе shortcut или сохранять prompt между перезапусками сервера.

## Decisions

Хранить текущий текст `Command2` в модели `Worktree` как строку, начальное значение которой равно `""`. View всегда передаёт это значение в input, чтобы первый документ явно содержал пустой `text`, а ответ на shortcut-событие заменял локальное Android-состояние поля.

Представить shortcut как типизированное page-local действие с текстом prompt. Encoder публикует одно backend-событие с этим текстом, а decoder принимает его только на экране выбранного worktree. Это не требует новых возможностей Android-клиента: он уже пересылает объект события кнопки и применяет возвращённый документ.

Не использовать существующее событие `run_claude`: кнопки отправляют `null` в envelope `value`, тогда как оно требует текст команды и запускает процесс. Отдельное shortcut-событие сохраняет выбор prompt и выполнение как разные действия.

## Risks / Trade-offs

- [Нажатие shortcut заменяет несохранённый текст, набранный в `Command2`] → Это соответствует явному требованию подставить выбранный prompt; объединение текста не вводится.
- [Текст prompt отражается в event object] → Значения являются фиксированными локальными shortcut-командами; дополнительные пользовательские параметры не поддерживаются.
