## Context

Мотивация и границы изменения описаны в `proposal.md`. Сейчас `Home.init` выбирает `Worktrees` или `Sessions` по `Runtime.environment`, запускает загрузку эмуляторов, а обработчик `Initialize_emulator` начинает загрузку выбранного списка. `Server.initialize` выполняет эту цепочку до приёма HTTP-запросов. Корневой `Home.view` уже размещает основной экран слева от эмулятора в ряду `2:1` с разделителем.

В `Home_components.Worktrees` и `Sessions` есть подходящий локальный шаблон: модель данных и ошибки, чистое представление, сообщение загрузки и конечная `Cmd.Run`. `Runtime.environment` хранит корень только для Claude; этот корень имеет другое назначение, чем рабочая директория нового экрана. Существующие тесты прямо проверяют старые стартовые состояния и команды, поэтому обновление затронет несколько backend-модулей и их интеграционные проверки.

## Goals / Non-Goals

**Goals:**
- Держать данные, ошибку и обновление каталогов внутри самостоятельного TEA-компонента, используя существующий механизм команд.
- Развести рабочую папку стартового списка и существующий параметр репозитория Claude без изменения CLI.
- Проверять файловый отбор настоящими временными каталогами, а взаимодействие компонентов — существующими проверками модели и JSON.

**Non-Goals:**
- Новый протокол, Android-рендерер, файловый браузер, хранение истории или сервис наблюдения за файлами.
- Рефакторинг всех прежних экранов, удаление агентных возможностей или новая навигация к ним.

## Decisions

### 1. Компонент `Directories` в `lib/home_components.ml`

Добавить модуль рядом с остальными компонентами, без отдельного слоя абстракций. Модель содержит зафиксированный корневой путь, последние успешно загруженные записи и ошибку. Сообщения включают запрос загрузки, её результат и `Click` с абсолютным путём каталога. Чистое `view` строит заголовок, путь, ошибку или пустое состояние через существующие `column`/`text`, а имена каталогов — через `button` с событием `Click`; список получает прокручиваемую область существующей взвешенной колонки.

Обработчик `Click` возвращает прежнюю модель и `Cmd.Run`, которая печатает одну строку в stdout backend, немедленно сбрасывает буфер и возвращает `None`. Для пути использовать стандартное экранированное строковое представление `Printf` (`%S`), чтобы управляющие символы не разбивали запись лога. Сам `update` не выполняет ввод-вывод. Никаких полей выбора, переходов, повторного чтения каталога или вызовов агента клик не добавляет; существующий HTTP-механизм команд возвращает документ с тем же состоянием. Это конкретное действие через обычное сообщение компонента, без отдельного расширяемого механизма обработчиков.

Альтернатива — разместить всё в `Home` — смешивает файловый компонент с маршрутизацией. Отдельный новый файл не нужен: самостоятельный модуль соответствует текущему стилю и требованию отдельного компонента.

### 2. Однократное чтение рабочей директории при инициализации

`Home.init` получает `Sys.getcwd ()` при создании нового состояния backend и сохраняет его в модели `Directories`. Обработчик завершения инициализации эмуляторов запускает загрузку уже созданного компонента, а не выбирает `Worktrees` или `Sessions`. Ошибка загрузки эмуляторов не препятствует загрузке каталогов. `Refresh` использует сохранённый путь.

Не использовать `Runtime.Claude.root` и не превращать его в универсальный корень: позиционный путь Claude уже относится к репозиторию, а в OpenCode такого поля нет. Существующий `--agent` остаётся обязательным, его метка отображается в общей оболочке.

### 3. Файловая система через стандартные средства

Небольшая функция `Runtime.load_directories` читает непосредственные имена через `Sys.readdir`, получает `Unix.lstat` для каждого, оставляет `S_DIR`, сортирует по `st_mtime` по убыванию и `String.compare` имени при равенстве, затем берёт первые десять. Ссылки исключаются самим `lstat`, скрытые имена не фильтруются. Достаточно результата с именем и временем; время используется для сортировки, форматирование даты на экране не требуется.

Альтернативы — shell-команда `ls`, рекурсивный обход, Git timestamps и новая библиотека — не нужны для буквального требования о дате изменения самой папки. Если чтение или метаданные завершаются ошибкой, команда возвращает ошибку целиком; компонент сохраняет предыдущий успешный список. Отдельного протокола частичных результатов нет.

### 4. Включение в текущую маршрутизацию и HTTP

Добавить вариант экрана `Directories` и обёртку его сообщений в `Home`, маршруты `view`, `Refresh`, `Back`, результатов загрузки и `Click`. Корневой `Refresh` касается только каталогов, события `Emulator_msg` продолжают обновлять только панель эмулятора. Общий ряд и его оформление переиспользуются.

В `Server` согласовать первоначальное placeholder-состояние, `reset`/`initialize` и сопоставления вариантов экрана. Новый экран не должен попадать в пути отправки prompt/command. В `decode` отвергать клиентскую подделку нового внутреннего сообщения `Directories.Loaded`, как уже делается для результатов загрузки сессий. Существующие конечные команды обеспечивают NDJSON-ответ на обновление без отдельного endpoint.

```text
Home.init
    |
    v
Directories state + emulator initialization
    |
    v
Directory load --> loaded entries / component error
    |
    v
+--------------------------+-------------+
| Agent label              | Emulator    |
| Directories              |             |
| Startup path             | Controls    |
| Up to 10 names           | Preview     |
+--------------------------+-------------+
         2 parts               1 part
```

Прежние экранные компоненты сохраняют свои локальные переходы и проверки. Новый экран не содержит элементов перехода к ним: пользователь согласовал замену стартового экрана и клик, который пока только логирует путь. Спецификации OpenCode поэтому говорят об активном экране сессий, а не называют его корневым стартовым экраном.

## Risks / Trade-offs

- `mtime` папки не отражает редактирование вложенного исходника → явно закрепить эту семантику в спецификации, документации и проверке отсутствия рекурсивного влияния.
- Полный просмотр и сортировка требуют `O(n)` метаданных и `O(n log n)` времени для непосредственных записей → достаточно для этого этапа; в реализации отметить `ponytail:` предел полного чтения/сортировки и пересмотр в пользу ограниченного top-10, если измерения на больших папках покажут проблему.
- Изменение файловой системы во время чтения может привести к ошибке всей загрузки → сохранить последний успешный список и дать повторить существующим `Refresh`, без скрытого пропуска неизвестных записей.
- Замена стартового экрана убирает пользовательский вход в прежние агентные списки → явно обозначить это в README; выбор каталога и дальнейшую навигацию проектировать отдельным изменением по запросу.
- Существующие тесты создают модели прежних экранов и проверяют исчерпывающие варианты → обновить стартовые ожидания и сопоставления, сохранив прямые проверки прежних компонентов.

## Migration Plan

Изменение не требует миграции данных. Обновить backend, проверки и README, затем перезапустить backend: первый документ в обоих режимах должен содержать каталоги. Проверить сценарий OpenCode без запущенного сервера и Claude из папки без Git, не меняя правил CLI. При необходимости отката вернуть предыдущую версию backend и перезапустить её; состояние UI существует только в памяти.

Для реализации запланировать `dune fmt` и сборку backend. Устройство для любых device-проверок — только `abf51f11`, с `export ANDROID_SERIAL=abf51f11`; если оно недоступно, прекратить тестирование и сообщить блокер. Ни запуск иных устройств, ни изменение Android-кода для этого экрана не требуется.
