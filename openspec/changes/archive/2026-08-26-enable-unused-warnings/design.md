## Context

См. мотивацию в `proposal.md`. Проект использует Dune 3.24 и OCaml 5.4.1; библиотека, исполняемый файл и тесты определены в отдельных файлах `dune`, а общей корневой конфигурации флагов нет. `Makefile` выполняет `dune build` и CI-конфигурация отсутствует.

## Goals / Non-Goals

**Goals:**

- Единообразно сделать фатальными поддерживаемые предупреждения OCaml о неиспользуемых сущностях во всех целях Dune.
- Проверять лишние прямые зависимости из полей `libraries` через Dune.

**Non-Goals:**

- Не делать фатальными все предупреждения OCaml.
- Не искать неиспользуемые экспортируемые верхнеуровневые значения или модули между единицами компиляции.
- Не добавлять внешний линтер или зависимость.

## Decisions

- Добавить корневой файл `dune` с наследуемым `(env (_ ...))` и использовать `(:standard ...)`. Это применит флаги к `lib`, `bin` и `test`, не заменяя флаги Dune по умолчанию. Альтернатива с повторением `(flags ...)` в каждом существующем файле `dune` дублирует одну политику.
- Включить и сделать ошибками предупреждения `26`, `27`, `32..39`, `60`, `66`, `67` и `69`: это полный поддерживаемый OCaml 5.4 набор предупреждений с семантикой неиспользуемых сущностей. После `:standard` сначала передать `-warn-error -a`, потому что Dune в профиле разработки уже передаёт `-warn-error +a`, затем снова сделать фатальным только явный список. Использовать явные номера, а не `+a` или группы предупреждений, чтобы новая версия компилятора не сделала сборку непредсказуемо строгой.
- Дополнить цель `test` в `Makefile` запуском `dune build @unused-libs`. Эта встроенная цель Dune проверяет только лишние записи `libraries`; отдельный линтер для этого не нужен.

## Risks / Trade-offs

- Новые предупреждения могут выявить существующий код и временно сломать сборку → исправить выявленные случаи или явно обозначить намеренно неиспользуемые привязки через `_`.
- Проверка не находит весь неиспользуемый публичный API и модули с побочными эффектами → это ограничение статического анализа компилятора; не расширять объём внешними инструментами.
- Новая версия OCaml может добавить предупреждения о неиспользуемом коде → пересмотреть явный список при обновлении компилятора.

## Migration Plan

1. Добавить глобальные флаги и проверку `@unused-libs`.
2. Запустить `make test` и устранить обнаруженные нарушения.
3. При необходимости отката удалить новые настройки; код и данные миграции не требуют.
